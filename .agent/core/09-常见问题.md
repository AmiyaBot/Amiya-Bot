## 1. 启动与全局单例

| # | 现象 | 位置 | 原因与规避 |
| --- | --- | --- | --- |
| 1 | 只想读一个常量，却连带建目录、建库、发网络请求 | `core/__init__.py:25-39`、`:83-138` | **`import core` 会执行全部模块级副作用**：建目录、读配置、建库建表、构造 `bot`、挂 4 类钩子、发一次网络请求 |
| 2 | 离线环境下启动明显变慢 | `core/__init__.py:17` → `core/config/remote.py:12-23` | **`import core` 会同步请求 `{plugin}/api/v1/remote`**。失败则静默回退默认值，但会等到超时 |
| 3 | 换个目录运行就建出错误的目录 / 读不到配置 | `core/__init__.py:25`、`:27-28`、`core/database/__init__.py:10` 全是相对路径 | **CWD 必须是仓库根** |
| 4 | `import core` 报 `NameError: init_task` | `core/__init__.py:53-55` 引用 `:137` | **`exec_before_init` 依赖文件末尾定义的 `init_task`**；在模块加载完成前调用会炸 |
| 5 | 线上异常完全收不到 | `core/__init__.py:67` 的 `and instance` | **`send_to_console_channel` 静默失败**：没配 `BotAccounts.console_channel` 时异常全部丢失。先确认该字段有值 |
| 6 | 「只想加载插件」的脚本挂住不退出 | `core/__init__.py:137` 的 `init_task` 含阻塞协程 | **`run_amiya()` 不传 tasks 也不会退出**（`heartbeat` + `run_main_timed_tasks` 一直挂）。要退出得自己取消任务 |
| 7 | 资源下载失败直接崩进程，无堆栈提示 | `amiya.py:20-31` | **`except KeyboardInterrupt` 捕不到资源下载失败**——它只处理 Ctrl-C |
| 8 | `run_test.py` / `run_plugin_server.py` 起不来 | `run_test.py:26`、`run_plugin_server.py:52` | 两者把**单个协程**当 `tasks` 传给 `run_amiya(tasks: List[Coroutine] = [])`，而签名期望列表 |
| 9 | 打包成 exe 后 `ModuleNotFoundError`，源码下正常 | `core/frozen.py:3-15` | **不要删 `core/frozen.py` 里的任何 import**——它们是 PyInstaller 的收集锚点，删了只在打包产物上炸（[详见](01-启动与单例.md#22-一串保活-importcorefrozenpy3-15)） |

## 2. 插件加载

| # | 现象 | 位置 | 原因与规避 |
| --- | --- | --- | --- |
| 10 | 子目录里的插件永远不加载 | `core/plugins/__init__.py:23-29` | **`plugins/` 只扫顶层**（`os.walk` 后立刻 `break`）。插件只能平铺在 `plugins/` 根目录 |
| 11 | 手动放解压目录无效 | `core/plugins/__init__.py:25` | **只认 `.zip`**，解压目录不在扫描范围 |
| 12 | 插件没装上，日志只有一行 | `core/plugins/__init__.py:39` | **`load_plugin_file` 用 `log.catch` 吞掉所有异常**。构造期的 `ValueError` 原因看不到——写插件时先在本地单独 import 一次 |
| 13 | 插件加载异常 / `KeyError` | `core/plugins/__init__.py:83` | `:83` 用 `plugins[...]` 而非 `exists[...]`：依赖已装在 bot 上但不在本批扫描结果中时崩 |
| 14 | `'1.0'` 与 `'1.0.0'` 两处结论相反 | `core/plugins/__init__.py:83` vs `amiyaBotPluginInstance.py:470-491` | **版本比对语义两处不一致**：依赖检查用**字面量相等**，配置升级用**数字比较**。写 `Requirement` 用精确版本号 |
| 15 | 插件数量对不上，无明显报错 | `core/plugins/__init__.py:50-55` | **单个插件安装失败只记日志**，其余继续。查 `logs/running.log` 里的 `plugin install error(...)` |
| 16 | 安装失败的半成品 zip 留在 `plugins/` | `core/server/plugin.py:150-157` | 失败时**不删除已落盘的文件**，下次启动会重复尝试加载并再次报错 |
| 17 | 重复安装返回「插件安装失败」但其实已装 | `core/server/plugin.py:154-157` + `core/plugins/__init__.py:47-48` | 已装插件被跳过 → `count=0` → 端点返回 500。**误导性错误信息**，去 `bot.plugins` 确认实际状态 |
| 18 | `plugins/` 里莫名多出 zip | `core/plugins/__init__.py:120-121` | 远端补拉的依赖**会持久化落盘**。这是设计，但排查「哪来的插件」时要记得 |

## 3. 插件配置双轨

| # | 现象 | 位置 | 原因与规避 |
| --- | --- | --- | --- |
| 19 | 插件直接加载失败（只留一行日志） | `amiyaBotPluginInstance.py:61-62`、`:227-228` | **提供 `channel_config_default` 必须同时提供 `global_config_default`；提供 schema 必须提供 default**。降级链需要全局兜底 |
| 20 | 配置项全是 None，插件不报错 | `amiyaBotPluginInstance.py:278-288` | **配置文件路径拼错 = 静默无配置**：`os.path.exists` 为假时 `__parse_to_json` 隐式返回 `None` |
| 21 | `.yml` 配置文件加载失败 | `amiyaBotPluginInstance.py:279` | 判断是 `endswith('yaml')`，**`.yml` 不被识别**，会走 `json.load` 并失败 |
| 22 | 无法表示「空的全局配置」 | `amiyaBotPluginInstance.py:258-259` | **空 dict `{}` 等于「没配置」**（`if not value` 短路） |
| 23 | 新配置项升级后没自动补齐 | `amiyaBotPluginInstance.py:315`、`:319`、`:345`、`:349`；`core/server/plugin.py:137`、`:140` | **`set_config` 与控制台写配置都会抢先把 version 提到最新**，从而跳过下次启动的 `merge_dict` 升级 |
| 24 | 能写入违反 schema 的值 | `amiyaBotPluginInstance.py:416-442`；`core/server/plugin.py:135`、`:141` | **`set_config` 与控制台写入都不做 Schema 校验**；schema 只在构造期校验 default |
| 25 | 控制台写全局配置后行为异常 | `core/server/plugin.py:22` vs `amiyaBotPluginInstance.py:20` | **`channel_id=None` vs `''`**：`SetConfigModel.channel_id` 默认 `None`，但全局记录的键是 `''`。传 None 会写 NULL |
| 26 | 「配置没生效」找不到异常 | `amiyaBotPluginInstance.py:352-414` | **`get_config` 永不抛异常，只返回 `None`**。排查方式是打印返回值 + 调高日志级别看 `:378`/`:384`/`:411` 的 debug 提示 |
| 27 | 用户配置莫名回默认值，审计表里查不到 | `amiyaBotPluginInstance.py:98-101`、`:119-122` | **数据库 JSON 损坏会被静默重置为默认**，**且不写审计记录** |
| 28 | 插件版本号导致 `ValueError` | `amiyaBotPluginInstance.py:472-473` 的 `int(num)` | **插件 `version` 必须是纯数字点号格式**；`'1.0-beta'`、`'v1'` 都会炸 |
| 29 | 多个插件实例配置串味 / 并发写丢更新 | `amiyaBotPluginInstance.py:261-262`、`:416-442` | dict 形式的 default **不深拷贝**；`json_config` 是读改写模式（last-write-wins）。不要在模块级复用同一个 dict |
| 30 | 查频道配置抛异常 | `amiyaBotPluginInstance.py:291-292`、`:305-306` | **空字符串被保留给全局**，不能用 `''` 查频道配置 |

## 4. 数据库

| # | 现象 | 位置 | 原因与规避 |
| --- | --- | --- | --- |
| 31 | `import core` 直接 `KeyError: 'mode'` | `core/database/__init__.py:6` | **删 `config/database.yaml` 会导致 `import core` 失败** |
| 32 | 明明配了 mysql 却用了 sqlite | `core/database/__init__.py:6` 精确相等 | **`mode` 大小写敏感**，`'MySQL'` 被判为 sqlite |
| 33 | 想跨库 JOIN / 做跨库事务 | 各自独立的 `connect_database` | **5 个库不能跨库 JOIN，也没有跨库事务**。例如 `core/server/user.py:36-38` 的三条 UPDATE 无法原子化 |
| 34 | 缺 `build/` 目录时整个 `import core` 失败 | `core/database/bot.py:5` → `core/cosChainBuilder.py:7` → `build/uploadFile.py` | **数据库模块依赖构建工具目录**。打包时务必带上 `build/` |
| 35 | 干员稀有度比较恒为 False | `core/database/bot.py:155` | **`OperatorIndex.rarity` 是字符串**（如 `'6'`），而内存对象 `ArknightsGameData.operators[...].rarity` 是 int。**两者不要混用** |
| 36 | 用户数据没存上，但无任何报错 | `core/database/user.py:63-64`、`:69-70` | **`set_meta_value` 超限静默返回 `None`**：单项 > 20KB 或单用户总量 > 1MB 时直接丢弃；且长度按**字符数**算，中文下实际字节数约 3 倍 |
| 37 | 纯查询也插入了 4 条记录 / 外键约束报错 | `core/database/user.py:76-77`、`:81-84` | **`get_user_info` 用 `get_or_create`**，读操作也有写副作用；**`get_user` 必须先建 `User` 再建 `UserInfo`**，顺序不能换 |
| 38 | 加资源点的数量不对 | `core/database/user.py:97` 的 `point_max - user.jade_point_max` | **`add_jade_point` 的 `point_max` 语义是「新上限」**，不是「上限值」。误传会算出错误的 surplus |
| 39 | 删用户后残留数据 / 图鉴读写不一致 | `core/database/user.py:124`；`gachaBuilder.py:590`、`:577-580`、`box.py:21-22` | **`OperatorBox.user_id` 不是外键**（删 User 不级联）；**`operator` 是手写序列化格式**（`名字:稀有度:数量` 用 `|` 拼接），改动需同步三处 |
| 40 | dashboard 统计端点越来越慢 | `core/database/messages.py:13-19` | **`MessageRecord` 无索引**，`create_time` 范围查询全表扫描 |

## 5. 控制台端点

| # | 现象 | 位置 | 原因与规避 |
| --- | --- | --- | --- |
| 41 | 重命名方法后前端 404 | `core/__init__.py:33` ↔ `core/server/replace.py:95` | **路由路径 = 方法名的驼峰形式**（snake_case → camelCase）。**改方法名 = 改 API 路径**，且没有路由清单可查 |
| 42 | 某些端点整片消失（404，无报错） | `core/server/__init__.py:1` | **删掉这一行里的任何导入项 = 对应模块全部端点静默消失** |
| 43 | 编辑 websocket 账号必然报「端口不能重复」 | `core/server/bot.py:83-85` vs `:79-81` | **`edit_bot` 的端口校验没排除自身**（对比 appid 校验写了 `exists and`）。绕过：先把 `adapter` 临时改成别的值，或直接改库 |
| 44 | 卡池改成全新名字时端点 500 | `core/server/gacha.py:47-49` 缺 `pool and` | `Pool.get_or_none` 返回 `None` 后访问 `pool.id` 抛 `AttributeError`。改名要确保新名字已存在，或直接改库 |
| 45 | 更新替换规则后它从免鉴权端点消失 | `core/server/replace.py:54` + 模型默认 `None`（`:14-15`） | **`update_replace` 会把 `is_global`/`is_active` 写成 NULL**，之后 `is_global == 1` 过滤匹配不到。前端必须始终传这两个字段 |
| 46 | 插件升级失败回滚后配置与新版本不兼容 | `core/server/plugin.py:171`、`:183-184` | **`upgrade_plugin` 回滚不恢复配置**：构造副作用已发生，库里的 version 已是新版，回滚重装旧插件时**不触发降级**（[详见](08-控制台API-业务接口.md#25-upgrade_plugin--升级与回滚161-187)） |
| 47 | 升级途中异常，既没回滚又留下新 zip | `core/server/plugin.py:162-185` | **`upgrade_plugin` 没有 try/except**；`:170` 的 `bot.plugins[plugin_id]` 还可能 `KeyError`（且此时新 zip 已落盘） |
| 48 | 启动账号时端点和消息处理卡顿 | `core/server/bot.py:100` | **`run_bot` 是 `async def` 但没有 `await`**，且 `bot.append(..., launch_browser=True)` 会拉起 Playwright |
| 49 | gamedata 插件没装也返回「更新成功」 | `core/server/opterator.py:48-50` + `arknightsGameData.py:24` 空列表 | **`update_setting` 走类变量注册**，插件未装时 `initialize_methods` 为空，什么都不做但仍返回成功 |
| 50 | 控制台端口暴露到公网 = 数据泄露 | `core/__init__.py:32-36`、`:41` | **三个免鉴权路径暴露数据**：`/plugins` 是静态目录，连插件源码 `*.py` 一起暴露。**生产环境绝不要把控制台端口对公网开放** |
| 51 | 插件安装可写到 `plugins/` 之外 | `core/server/plugin.py:150-151` | **`packageName` 无路径穿越校验**。内网控制台风险可接受，但要知道 |
| 52 | 拉日志把内存吃满 | `core/server/dashboard.py:20` | **`get_log` 的 `lines` 无上限**，`read_tail` 会一直往前读到文件头 |
| 53 | 消息统计时间轴以 `24:00` 开头 | `core/server/dashboard.py:39-40`、`:45` | **0 点被映射为 `24:00`**（为了让横轴连续递减），与直觉不同 |
| 54 | 消息统计端点高流量下内存压力大 | `core/server/dashboard.py:33-35` | 查询**无上界、无 limit**，靠 `:46` 的 `if hour in res` 兜住窗口外的数据 |

## 6. 「不要做」清单

1. **不要删 `core/frozen.py` 里的任何 import**（`core/frozen.py:3-15`）——PyInstaller 的收集锚点，**删了只在打包产物上炸**。
2. **不要改 `core/server/*.py` 里的方法名**——那等于改 API 路径（坑 #41）。
3. **不要改 `QueryData` 的字段名**（`core/server/__model__.py:6-8`）——前端按驼峰传参。
4. **不要删 `core/server/__init__.py:1` 的任何一个导入项**——对应端点会静默消失（坑 #42）。
5. **不要在 `core/__init__.py:83-94` 的 `message_before_handle` 里加耗时逻辑**——它是每条消息的热路径。
6. **不要把 `plugins/` 的子目录当成插件目录**——只扫顶层（坑 #10）。
7. **不要假设 `get_config` 会报错**——它只返回 `None`（坑 #26）。
8. **不要用 `.yaml` 之外的后缀**存放 YAML 配置（坑 #21）。
9. **不要在没有 `channel_id=''` 意识的情况下写 `PluginConfiguration`**（坑 #25）。
10. **不要在 `upgrade_plugin` 之前删旧插件文件**——回滚需要它（`core/server/plugin.py:171`）。
11. **不要把本目录文档里的行号当成永久契约**——改动 `core/`、`amiya.py` 或插件源码后，引用会失效，需同步核对。
