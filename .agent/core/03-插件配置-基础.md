# core 运行时 · 插件配置：双轨制与读写

`core/plugins/customPluginInstance/amiyaBotPluginInstance.py`（518 行）是宿主提供给插件的基类。它解决插件的核心难题：**同一份配置，既要能全局设一份，又要能按频道/群各设一份**。

- 存储：`amiya_plugin` 库的 `PluginConfiguration`，主键 `(plugin_id, channel_id)`。
- **`channel_id == ''` 代表全局配置**；任何非空值代表某个频道/群。
- 读走五级降级链，**永不抛异常**；写是「读整份 → 改一个键 → 写回整份」。

升级与审计、`Requirement`、版本号比较见 [插件配置 · 升级与审计](04-插件配置-升级与审计.md)。

相关：[插件加载器](02-插件加载器.md) · [数据库 · 其余表](06-数据库-其余表.md) · [常见问题](09-常见问题.md)

## 1. 类型别名与全局频道键（`:16-20`）

```python
JSON_VALUE_TYPE = Optional[Union[bool, str, int, float, dict, list]]      # :16
CONFIG_TYPE = Optional[Union[str, dict]]                                  # :17
DYNAMIC_CONFIG_TYPE = Optional[Union[str, dict, Callable[[], Union[dict, list]]]]   # :18

global_config_channel_key = ''                                            # :20
```

**`global_config_channel_key = ''`（`:20`）是整个双轨制的地基**：

- 配置存在 `PluginConfiguration` 表，主键是 `(plugin_id, channel_id)`（`core/database/plugin.py:22`）。
- **`channel_id == ''` 就代表「全局配置」这条记录**；任何非空 `channel_id` 代表某个频道/群的配置。
- 所以代码里到处是 `channel_id == global_config_channel_key` 的判断（`:70`、`:104`、`:188`、`:291`、`:305`、`:357`、`:364`、`:417`、`:437`）。
- **副作用**：因为用空字符串表示全局，`__get_channel_config` 会在 `not channel_id` 时直接抛异常（`:291-292`）。也就是说**不能用空字符串查频道配置**——它被保留给全局了。
- 用 `''` 而不是 `None` 的原因：数据库列是非空的 `CharField`（`core/database/plugin.py:17`），用空串可以避免 NULL 在复合主键里的比较问题。

## 3. 构造期硬约束

### 3.1 构造流程（`:46-62`）

```python
self.__channel_config_default = self.__parse_to_json(channel_config_default)   # :46
self.__global_config_default = self.__parse_to_json(global_config_default)     # :47

self.__channel_config_schema = channel_config_schema       # :49
self.__global_config_schema = global_config_schema         # :50

# 原地获取一次,目的是校验
_ = self.__get_dynamic_channel_config_schema()             # :53
_ = self.__get_dynamic_global_config_schema()              # :54

self.__deprecated_config_delete_days = deprecated_config_delete_days   # :56

self.validate_schema()                                     # :58

# 执行一个额外的验证，提供了频道配置的，必须提供全局配置
if self.__global_config_default is None and self.__channel_config_default is not None:   # :61
    raise ValueError('If you provide channel default, you must also provide global default.')   # :62
```

- **default 立即解析**（`:46-47`），schema **延迟解析**（`:53-54`）——因为 schema 参数可能是 `Callable`（`DYNAMIC_CONFIG_TYPE`，`:18`），必须在**运行时**（而不是写代码时）求值。
- `:53-54` 的注释「原地获取一次,目的是校验」：**调用一次以触发 `__parse_to_json` 的类型检查**，结果被丢弃（赋给 `_`）。这能在构造期就把「schema 传了个乱七八糟的东西」暴露出来，而不是等到第一次 `validate_schema`。
- `validate_schema()`（`:58`）在构造期立刻跑（见 §7）。

### 3.2 两条硬约束（都 `raise ValueError`）

1. **提供 channel default 必须提供 global default**（`:61-62`）：`'If you provide channel default, you must also provide global default.'`
2. **提供 schema 必须提供 default**（`:227-228`）：`'If you provide schema, you must also provide default.'`

为什么？因为 `get_config` 的降级链（§5）最终要落到全局配置上；没有全局配置就没有兜底，降级链会断。

> ⚠️ **这些 `ValueError` 会让整个插件加载失败**，但 `load_plugin_file` 用 `log.catch` 吞异常（`core/plugins/__init__.py:39`），启动日志里只有一行 `plugin load error(...)`，**看不到 `ValueError` 的原因**。写插件时建议先在本地单独 import 一次，让异常真正抛出来。

## 4. `__parse_to_json`：三种入参（`:253-288`）

插件作者最常打交道的函数，支持三种写法：

```python
@staticmethod
def __parse_to_json(value: DYNAMIC_CONFIG_TYPE) -> CONFIG_TYPE:
    if callable(value):                    # :255-256
        value = value()

    if not value:                          # :258-259
        return None

    if isinstance(value, dict):            # :261-262
        return value

    if not isinstance(value, str):         # :264-265
        raise ConfigTypeError(value)

    try:
        res = json.loads(value)            # :268
        if not isinstance(res, dict):      # :270-271
            raise ConfigTypeError(value)
        return res
    except json.JSONDecodeError:
        pass                               # :274-275

    # json 或 yaml 文件
    if os.path.exists(value):              # :278
        if value.endswith('yaml'):         # :279
            res = read_yaml(value, _dict=True, _refresh=True)   # :280
        else:
            with open(value, 'r', encoding='utf-8') as file:     # :282-283
                res = json.load(file)

        if not isinstance(res, dict):      # :285-286
            raise ConfigTypeError(value)

        return res
```

| 入参形式 | 分支 | 例子 |
| --- | --- | --- |
| **callable** | `:255-256`，先调用取值 | `global_config_default=lambda: {...}` |
| **dict** | `:261-262`，直接返回（**不深拷贝**） | `{'a': 1}` |
| **JSON 字符串** | `:268-273`，`json.loads` 后必须是 dict | `'{"a": 1}'` |
| **文件路径** | `:278-288`，`.yaml` 走 `read_yaml`，其余走 `json.load` | `f'{curr_dir}/config_default.yaml'` |
| **假值**（`None`/`''`/`{}`/`[]`/`0`） | `:258-259`，返回 `None` | 未提供配置 |

实际用法：gacha 插件用 JSON 文件 `global_config_default=f'{curr_dir}/config/global_config_default.json'`（`pluginsDev/src/arknights/gacha/main.py:71-72`）；gamedata 插件用 `.yaml`（`pluginsDev/src/arknights/arknightsGameData/builder/__init__.py:46-47`）。

**容易踩的点**：

- **`if not value: return None`（`:258`）会把空 dict `{}` 也当成「未提供」**。所以插件不能通过传 `{}` 表示「我有一个空的全局配置」——那等同于没配，随后 `:61` 的硬约束会因 `channel_config_default` 非空而报错。
- **JSON 字符串分支只捕获 `JSONDecodeError`**（`:274`）。若字符串恰好是一个存在的文件路径，链会自然走到 `:278`。
- **文件路径分支没有 `else` 返回**：若 `os.path.exists(value)` 为假，函数**隐式返回 `None`**（`:288` 之后没有代码）——**「传了个不存在的路径」会被静默当成「没配置」**。路径拼错时插件不会报错，只是配置全为默认/None。
- `.yaml` 判断用的是 `value.endswith('yaml')`（`:279`），**不是** `.yaml`。所以 `foo.yaml` ✅、`foo.yml` ❌（会走 `json.load` 并失败）。
- `read_yaml(..., _dict=True, _refresh=True)`（`:280`）：`_dict=True` 让它返回普通 dict（非 `attridict`），`_refresh=True` 绕过缓存。见 `core/util/yamlManager.py:15-28`。
- `value` 是 dict 时**直接返回原对象引用**（`:261-262`），后续 `merge_dict` 可能原地修改它。插件如果复用同一个模块级 dict 传多个实例，会出现**配置串味**。

### 4.1 `ConfigTypeError`（`:445-450`）

继承 `TypeError`，只在 `__parse_to_json` 的三处抛出（`:265`、`:271`、`:286`）。错误信息列出三种合法形式：**json 字符串 / 文件路径 / dict**。它只保存 `type(value)` 而不保存值本身（`:447`）——避免把可能很大的配置内容打进日志。

## 5. 内部读写函数（`:290-350`）

| 函数 | 行号 | 行为 |
| --- | --- | --- |
| `__get_channel_config(channel_id)` | `:290-302` | `channel_id` 为空或等于全局键 → **抛 `ValueError`**（`:291-292`）；查不到 → `None`（`:296-297`）；JSON 损坏 → 抛 `ValueError('The config in database is not a valid json.')`（`:301-302`） |
| `__set_channel_config(channel_id, value)` | `:304-320` | 同样的空值校验（`:305-306`）；`get_or_none` 后 create 或 save（`:310-320`），**同时写 `version=self.version`**（`:315`、`:319`） |
| `__get_global_config()` | `:322-333` | 查全局记录；**查不到时返回 `copy.deepcopy(self.__global_config_default) or {}`**（`:328`） |
| `__set_global_config(value)` | `:335-350` | 与 `__set_channel_config` 对称 |

**关键差异**：`__get_global_config` 在**无记录**时返回默认值的深拷贝（`:328`），而 `__get_channel_config` 无记录时返回 `None`（`:296-297`）。这个不对称是刻意的——全局配置永远有值（保证降级链有终点），频道配置可以为空（表示「跟随全局」）。

`copy.deepcopy`（`:328`）很重要：直接返回 `self.__global_config_default` 的话，调用方 `set_config` 里的 `json_config[config_name] = ...`（`:434`）会**污染插件自己的默认值**，导致后续所有降级都返回被改过的「默认值」。

## 6. `get_config`：五级降级链（`:352-414`）

签名：`get_config(self, config_name: str, channel_id: str = None) -> JSON_VALUE_TYPE`

整体结构是**先处理频道级，再降级到全局级**：

```python
# 开发的思路改变了，现在以GUI为准，因此，如果插件没有提供channel_default，就表示该插件不支持设置频道级别配置，直接降级。
if self.__channel_config_default is None:                   # :354
    if channel_id and channel_id != global_config_channel_key:   # :357
        json_config = self.__get_channel_config(str(channel_id)) # :358
        if json_config is not None:
            if config_name in json_config:
                return json_config[config_name]              # :361
else:                                                        # :363
    if channel_id and channel_id != global_config_channel_key:   # :364
        json_config = self.__get_channel_config(str(channel_id)) # :365
        if json_config is not None:
            if config_name not in json_config:               # :369
                if config_name in self.__channel_config_default:
                    log.debug(...)                           # :378
                    return copy.deepcopy(self.__channel_config_default[config_name])   # :379
            elif json_config[config_name] is None:           # :383
                log.debug(...)                               # :384
            else:
                value = json_config[config_name]             # :386
                if not is_empty_value(value):                # :390
                    return value                             # :391
```

### 6.1 两条主分支（`:354` vs `:363`）

| 插件是否提供 `channel_config_default` | 行为 |
| --- | --- |
| **没有提供**（`:354` 为真） | 「插件作者压根没打算支持频道级配置，只是借用这个功能」。此时**无条件读库里的值并返回，不做 default 兜底**（`:357-361`），能取到就返回 |
| **提供了**（`:363` 的 else） | 走**完整的频道级降级逻辑**（`:364-391`） |

### 6.2 频道级内部的四种结果（`:363-391`）

| 情况 | 行号 | 结果 |
| --- | --- | --- |
| 频道记录不存在 | `:366` | 落到全局（`:394` 起） |
| 记录存在但缺该 key | `:369-379` | 若 default 里有 → 返回 **default 的深拷贝**（`:379`）；否则落到全局 |
| 记录里有但值为 `None` | `:383-384` | 记 debug 日志后**落到全局**（`elif` 分支没有 return） |
| 记录里有且值非空 | `:386-391` | 返回该值；但若 `is_empty_value(value)` 为真（`:390`）→ **落到全局** |

`:369-379` 的注释解释了「为什么缺 key 是不正常的」：*「通过GUI配置配置项的时候，是没法删除项的。所以出现不存在的项要么是因为新配置加入了，但是由于某些原因没有补。或者，可能是插件开发者在调用时传入了错误的配置项name」*——**既能兜住宿主补配置失败，也能兜住插件自己拼错 key**，同时打 debug 日志提醒。

`:383` 的特殊处理：*「界面是不可能把一个配置项改成None的，因此出现None必是因为插件开发者代码中设置了None」*——所以 `None` 一律降级。

### 6.3 全局级部分（`:394-414`）

```python
if self.__global_config_default is None:                    # :394
    json_config = self.__get_global_config()                # :397
    if json_config is not None:
        if config_name in json_config:
            return json_config[config_name]                 # :400
    return None                                             # :401
else:                                                       # :402
    json_config = self.__get_global_config()                # :403
    if json_config is not None:
        if config_name in json_config:
            return json_config[config_name]                 # :406
        else:
            log.debug(...)                                  # :411
            if config_name in self.__global_config_default:
                return copy.deepcopy(self.__global_config_default[config_name])   # :413
    return None                                             # :414
```

- 同样是「有 default 就兜底、没 default 就只读库」的两分支。
- **`__get_global_config()` 在无记录时返回 default 深拷贝**（`:328`），所以 `:402` 分支下 `config_name in json_config` 通常为真，`:411` 的告警路径只在「有新配置项但库里没有」时触发。

### 6.4 完整降级链

```
① 频道配置记录中的值（非 None、非 empty）
      ↓ 缺失 / None / empty
② 频道默认配置中的值（仅当插件提供了 channel_config_default）
      ↓ 缺失
③ 全局配置记录中的值
      ↓ 缺失（且无 global_config_default 时）
④ 全局默认配置中的值
      ↓ 缺失
⑤ None
```

> ⚠️ **`get_config` 永远不会抛异常，只会返回 `None`。** 「配置没生效」的排查方式是打印 `get_config` 的返回值，而不是找异常。调高日志级别能看到 `:378` / `:384` / `:411` 三条 debug 提示，它们会明确告诉你降级到了哪一层。
>
> ⚠️ **`:357` 与 `:364` 条件是 `channel_id and channel_id != global_config_channel_key`**。因此**传入 `channel_id=''`（全局键）会等同于不传 channel**，直接走全局分支（`:425`）。这是有意的。

### 6.5 `is_empty_value`（`:453-467`）

```python
def is_empty_value(value: JSON_VALUE_TYPE):
    """
    此处是为了表明逻辑，未来这里会加入可能的诸多检查。
    目前，因为前端界面删除所有条目后，实际存储的是空数组/空字符串。
    """
    if value == []:          # :460-461
        return True
    if isinstance(value, str):   # :463
        if value == '':          # :464-465
            return True
    return False                 # :467
```

- **只判定两种值**：空列表 `[]` 与空字符串 `''`。
- 判定依据来自**前端 GUI 的存储行为**（注释 `:456`）：界面里删空一个多选项，存下来的是 `[]`；清空一个文本框，存下来的是 `''`。这两种值在业务语义上等于「未设置」，所以要降级到下一层。
- **`0`、`False`、`{}` 都**不**算 empty**。所以布尔开关设为 `False` 会正常返回 `False`，不会被误降级。
- `:460` 用的是 `value == []`，对非 list 类型做相等比较是安全的（`0 == []` 为 `False`）。

## 7. `set_config`（`:416-442`）

```python
def set_config(self, config_name: str, config_value: JSON_VALUE_TYPE, channel_id: str = None):
    if channel_id and channel_id != global_config_channel_key:      # :417
        json_config = self.__get_channel_config(str(channel_id))    # :418
        if json_config is None:
            if self.__channel_config_default is not None:
                json_config = copy.deepcopy(self.__channel_config_default)   # :422
            else:
                json_config = {}                                    # :424
    else:                                                           # :425
        json_config = self.__get_global_config()                    # :426
        if json_config is None:
            if self.__global_config_default is not None:
                json_config = copy.deepcopy(self.__global_config_default)    # :430
            else:
                json_config = {}                                    # :432

    json_config[config_name] = config_value                         # :434

    if channel_id and channel_id != global_config_channel_key:      # :437
        self.__set_channel_config(str(channel_id), json_config)     # :438
    else:
        self.__set_global_config(json_config)                       # :440

    return self                                                     # :442
```

要点：

- **写之前先把整份配置读出来**（`:418`/`:426`），不存在就用 default 的深拷贝**补全基础**（`:422`/`:430`）——保证写回去的是一份**完整**配置，而不是只有一个 key 的碎片。
- **`copy.deepcopy`**（`:422`/`:430`）防止污染插件的 default（与 `:328` 同理）。
- **只改一个 key**（`:434`），其余保持原样。
- **返回 `self`**（`:442`），支持链式调用：`plugin.set_config('a', 1).set_config('b', 2)`。
- ⚠️ **`set_config` 会「抢先」把版本号提到最新**（通过 `__set_channel_config` / `__set_global_config` 内部的 `:315`、`:319`、`:345`、`:349`），**从而跳过下次启动时的 `merge_dict` 升级**。如果插件调用了 `set_config` 但期望后续自动补全新配置项，那不会发生。这是双轨制下最隐蔽的坑之一。详见 [升级与审计](04-插件配置-升级与审计.md#2-构造期的版本比对与-merge_dict-升级)。
- ⚠️ **`set_config` 不做 JSON Schema 校验**。schema 只在构造期校验 default（`:232`），以及控制台写入配置时（`core/server/plugin.py:123-144` 也**没有**校验）。所以**通过 `set_config` 能写入任何值，包括违反 schema 的**。

## 8. `validate_schema` 与 `get_config_defaults`

### 8.1 `validate_schema()`（`:220-234`）

```python
def validate_schema(self):
    for default, schema in (
        (self.__channel_config_default, self.__get_dynamic_channel_config_schema()),
        (self.__global_config_default, self.__get_dynamic_global_config_schema()),
    ):
        # 提供 Template 则立即执行校验
        if schema is not None:                                    # :226
            if default is None:                                   # :227
                raise ValueError('If you provide schema, you must also provide default.')   # :228

            # 立即校验 JsonSchema 是否符合
            try:
                jsonschema.validate(instance=default, schema=schema)   # :232
            except jsonschema.ValidationError as e:
                raise ValueError('Your json default does not fit your schema.') from e   # :234
```

- 用 `jsonschema.validate`（`:232`）——**仅校验 default，不校验用户已有配置**。
- **报错信息把原始异常用 `from e` 串起来**（`:234`），但**只保留了「Your json default does not fit your schema.」这一句**，丢掉了 jsonschema 的具体路径信息。要知道哪个字段不合规，得自己复现 `jsonschema.validate`。
- 两遍循环分别校验 channel 与 global（`:221-224`）。
- **只有 `schema is not None` 才校验**（`:226`）；没提供 schema 的插件完全不做结构约束。

### 8.2 `get_config_defaults()`（`:242-248`）

```python
def get_config_defaults(self):
    return {
        'channel_config_default': json.dumps(self.__channel_config_default),
        'channel_config_schema': json.dumps(self.__get_dynamic_channel_config_schema()),
        'global_config_default': json.dumps(self.__global_config_default),
        'global_config_schema': json.dumps(self.__get_dynamic_global_config_schema()),
    }
```

- **四个值都以 JSON 字符串返回**（`:244-247`），因为控制台前端需要字符串形式。
- **总是重新求值 schema**（`:245`、`:247` 调用 `__get_dynamic_*`）——所以 callable schema 每次调用都会被重新调用。
- 消费方是控制台端点 `core/server/plugin.py:88-97`（`get_plugin_default_config`）。

## 9. 配置双轨的坑位速查

| # | 坑 | 位置 | 表现 |
| --- | --- | --- | --- |
| 1 | 提供 channel default 必须同时提供 global default | `:61-62` | 构造直接 `ValueError`（且被 `log.catch` 吞掉，只留一行日志） |
| 2 | 提供 schema 必须提供 default | `:227-228` | 同上 |
| 3 | 配置文件路径拼错 = 静默无配置 | `:278-288` 无 else 返回 | 不报错，配置全为 None |
| 4 | `.yml` 不被识别为 YAML | `:279` 的 `endswith('yaml')` | `.yml` 会走 `json.load` 并失败 |
| 5 | 空 dict `{}` 等于「没配置」 | `:258-259` | 无法表示「空的全局配置」 |
| 6 | `set_config` 抢先把 version 提到最新 | `:315`、`:319`、`:345`、`:349` | **跳过下次启动的 `merge_dict` 升级**，新配置项不会自动补 |
| 7 | `set_config` 不做 Schema 校验 | 对比 `:220-234` 的 `validate_schema` | 能写入违反 schema 的值 |
| 8 | 控制台 `set_plugin_config` 也不校验 | `core/server/plugin.py:135`、`:141` 原样存字符串 | 非法 JSON 入库，下次加载被重置为默认 |
| 9 | 控制台写配置也抢版本号 | `core/server/plugin.py:137`、`:140` | 同 #6 |
| 10 | `channel_id=None` vs `''` | `SetConfigModel` 的 `channel_id: str = None`（`core/server/plugin.py:22`）vs `global_config_channel_key=''`（`:20`） | 传 None 会写 NULL，与全局记录的 `''` 不一致 |
| 11 | `get_config` 永不抛异常，只返回 `None` | `:352-414` | 「配置没生效」找不到异常，要靠 debug 日志 |
| 12 | `json_config` 是读改写模式 | `:416-442` | 并发写有 last-write-wins 丢失风险 |
| 13 | dict 形式的 default 不做深拷贝 | `:261-262` | 复用同一个模块级 dict 传多个实例会配置串味 |
| 14 | 用 `''` 查频道配置会抛异常 | `:291-292`、`:305-306` | 空串被保留给全局 |
