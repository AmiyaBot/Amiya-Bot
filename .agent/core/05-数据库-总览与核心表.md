# core 运行时 · 数据库总览与 `amiya_bot` 库

宿主有 **5 个库、19 张表**。库名硬编码，由 `config/database.yaml` 的 `mode` 在 sqlite / mysql 之间切换；每个库是独立的 peewee database 对象，**不能跨库 JOIN，也没有跨库事务**。

本文覆盖连接与建表机制，以及最大的 `amiya_bot` 库（9 张表，含账号表、适配器映射与卡池表）。其余四库见 [数据库 · 其余表](06-数据库-其余表.md)。

| 库 | 模块 | 表数 | 表 |
| --- | --- | --- | --- |
| `amiya_bot` | `core/database/bot.py` | 9 | `Admin` `BotAccounts` `FunctionUsed` `DisabledFunction` `OperatorIndex` `OperatorConfig` `Pool` `TextReplace` `TextReplaceSetting` |
| `amiya_group` | `core/database/group.py` | 3 | `Group` `GroupActive` `GroupSetting` |
| `amiya_message` | `core/database/messages.py` | 1 | `MessageRecord` |
| `amiya_plugin` | `core/database/plugin.py` | 2 | `PluginConfiguration` `PluginConfigurationAudit` |
| `amiya_user` | `core/database/user.py` | 4 | `User` `UserInfo` `UserGachaInfo` `OperatorBox` |

相关：[启动与单例](01-启动与单例.md) · [插件配置 · 基础](03-插件配置-基础.md) · [常见问题](09-常见问题.md)

## 1. 模式选择与库连接

`core/database/__init__.py` 全文 10 行，决定了**全部 5 个数据库落在哪里**：

```python
setting = read_yaml('config/database.yaml', _dict=True)   # :4
is_mysql = setting['mode'] == 'mysql'                # :6
config = MysqlConfig(**setting['config']) if is_mysql else None   # :7
if not is_mysql:
    create_dir('database')                           # :10
```

| 行号 | 说明 |
| --- | --- |
| `:4` | 读 `config/database.yaml`，**`_dict=True` 返回普通 dict**（不是 `attridict`），因为后面要 `**` 解包 |
| `:6` | **模式判定**：`setting['mode'] == 'mysql'`。精确相等，`'MySQL'` 会被判为 sqlite |
| `:7` | mysql 模式下用 `config` 段构造 `MysqlConfig`；**sqlite 模式下 `config = None`** |
| `:10` | sqlite 模式下**创建 `database/` 目录**（相对 CWD）。mysql 模式不建 |

`config/database.yaml:1-6` 默认内容是 `mode: 'sqlite'` 加一段 `config:（host/port/user/password）`。

- **默认是 sqlite**，落盘到 `database/*.db`。
- `config` 段在 sqlite 模式下**被完全忽略**（`:7`），但仍要求存在——mysql 模式要 `**setting['config']`，**缺这个键会 `KeyError`**。
- **`is_mysql` 和 `config` 会被全部 5 个库模块导入**（`bot.py:4`、`group.py:2`、`messages.py:2`、`plugin.py:3`、`user.py:4`），让每个库各自决定名字。例如 `connect_database('amiya_bot' if is_mysql else 'database/amiya_bot.db', is_mysql, config)`（`bot.py:18`）；其余四库同理，对应 `amiya_group.db` / `amiya_message.db` / `amiya_plugin.db` / `amiya_user.db`。
- **`config` 段里没有 `database` 名选项**——库名是硬编码的，mysql 模式下库名就是去掉 `.db` 的那部分。

**建表时机**：**导入 `core/database/*.py` 时**（`connect_database` + `@table` 装饰器）。触发导入的是 `core/__init__.py:15-16`（只导入 `messages` 和 `bot`）以及 `core/frozen.py:12-15`、`core/server/*.py` 等。sqlite 文件位于 `database/amiya_*.db`（**相对 CWD**）。**插件也能建表**——继承 `BotBaseModel` 等基类即可，表落在对应库。

> **Docker 部署注意**：`entrypoint.py:22-36` 的 `set_database()` 只在 `ENABLE_MYSQL` 环境变量非空时才把 `mode` 改成 `mysql`（`entrypoint.py:24-27`），其余情况**直接 `return`**。

## 2. 库连接与基类（`core/database/bot.py:1-23`）

```python
db = connect_database('amiya_bot' if is_mysql else 'database/amiya_bot.db', is_mysql, config)   # :18

class BotBaseModel(ModelClass):                      # :21
    class Meta:
        database = db                                # :23
```

`core/database/bot.py:8-16` **导入了 10 个适配器**（`qq_guild_shards` / `qq_global` / `qq_group` / `cq_http` / `mirai_api_http` / `onebot11` / `onebot12` / `com_wechat` / `test_instance` 等），是宿主里适配器知识的唯一汇聚点。

- **`BotBaseModel` 是所有 `amiya_bot` 表模型的基类**（`:21-23`），通过内部 `Meta.database = db` 绑定库。**它本身不是一张表**（没有 `@table`），是抽象基类。
- **插件可以复用这个基类建自己的表**——`pluginsDev/src/arknights/arknightsGameData/builder/common.py:31-35` 用 `@table class SkinsPathCache(BotBaseModel)` 建了皮肤缓存表；`pluginsDev/src/arknights/gacha/gachaBuilder.py:24-30` 用 `PoolSpOperator(BotBaseModel)` 建了卡池干员表。**插件的表也落在 `amiya_bot` 库里**。
- ⚠️ **导入顺序的坑**：`bot.py:5` 导入 `core.cosChainBuilder`，而 `core/cosChainBuilder.py:7` 反过来 `from build.uploadFile import COSUploader`。这条链让**数据库模块依赖了构建工具目录**——如果 `build/` 目录缺失，`import core.database.bot` 会失败，进而 `import core` 失败。**打包时务必带上 `build/`**。

## 3. `Admin` — 超级管理员（`:26-33`）

```python
@table
class Admin(BotBaseModel):
    account: Union[CharField, str] = CharField(unique=True)     # :28
    remark: Union[CharField, str] = CharField(null=True)        # :29

    @classmethod
    def is_super_admin(cls, user_id: str):                      # :31-33
        return bool(cls.get_or_none(account=user_id))
```

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `account` | `CharField` | **`unique=True`** | 用户 ID（QQ 号或频道用户 ID） |
| `remark` | `CharField` | `null=True` | 备注名 |

- **`is_super_admin`（`:31-33`）是宿主提供的权限判定**：`get_or_none` 查到即超管。
- 表名由 peewee 的 `@table` 从类名转蛇形得到，即 `admin`。
- 控制台可增删该表：`core/server/admin.py:38-50`。
- **`Union[CharField, str]` 是纯类型注解**（`:28`），运行时右侧 `CharField(unique=True)` 才是真的。这类注解在本仓库全部表中普遍存在，目的是让类型检查器把字段当成 `str` 用，**不影响运行**。

**`get_all_account()`（`:55-67`）**：遍历全部账号，**跳过 `is_start` 为 0 的**（`:61-62`），对每个账号调 `build_conf` 构造 `AmiyaBot(**conf)`（`:64-65`），返回实例列表。这个列表在 `core/__init__.py:39` 被展开成 `MultipleAccounts`。

### 4.1 `build_conf(item)` — 适配器映射（`:69-136`）

两张映射表：

```python
net_adapters = {                        # :71-77
    'mirai_api_http': mirai_api_http,
    'cq_http': cq_http,
    'onebot11': onebot11,
    'onebot12': onebot12,
    'com_wechat': com_wechat,
}
tx_adapters = {                         # :78-82
    'qq_guild': qq_guild_shards,
    'qq_group': qq_group,
    'qq_global': qq_global,
}
```

基础配置（`:84-88`）：

```python
conf = {
    'appid': item.appid,
    'token': item.token,
    'private': bool(item.private),      # :87 注意转 bool，库字段是 SmallIntegerField
}
```

**分支一：网络型适配器（`:90-95`）**

```python
if item.adapter in net_adapters:
    conf['adapter'] = net_adapters[item.adapter](
        host=item.host,
        ws_port=item.ws_port,
        http_port=item.http_port,
    )
```

5 个网络适配器（mirai / cq_http / onebot11 / onebot12 / com_wechat）**统一接收 `host`/`ws_port`/`http_port` 三个关键字参数**。

**分支二：腾讯系适配器（`:97-128`）**

- `qq_guild` 分支**只传 `shard_index` / `shards` + `sandbox=bool(item.sandbox)`**（`:104`）。
- 其余两个（`qq_group` / `qq_global`）走 else，需要构造 **ChainBuilder**。
- **端口默认 8086**（`:106`：`item.http_port or 8086`）。
- **`QQGroupChainBuilderOptions(host, port, temp_dir)`**（`:107`）：第 3 个参数是**临时文件目录 `./resource/group_temp`**，相对 CWD。

**ChainBuilder 的两条路（`:109-128`）**：

| 条件 | 行号 | 用的 ChainBuilder | 外部依赖 |
| --- | --- | --- | --- |
| `cos_config.activate` 为真 | `:109-114` | `COSQQGroupChainBuilder`（`core/cosChainBuilder.py:12`） | 腾讯云 COS 凭据（`config/cos.yaml`） |
| 否则 | `:116-128` | **就地定义的 `PenetrationChainBuilder`** | `config/penetration.yaml` 的端口映射 |

`PenetrationChainBuilder`（`:117`）在 else 分支内**于 `build_conf` 函数体中定义**，覆写 `domain` 属性（`:118-123`）：如果 `port` 在 `penetration_config.ports` 里就用映射到的域名 + `/resource`，否则调 `super().domain`（框架默认，通常是内网地址）。

- **每次调用 `build_conf` 都会新建一个类对象**——功能上没问题，但注意不要在里面加重的类级状态。
- **这个 config 字典随后被直接传给 `AmiyaBot(**conf)`**（`:65`），所以 `adapter` 键的值是**适配器实例**而非字符串。

**分支三：其它（`:130-134`）**

```python
if item.adapter == 'websocket':
    conf['adapter'] = test_instance(item.host, item.ws_port)   # :131

if item.adapter == 'kook':
    conf['adapter'] = KOOKBotInstance                            # :134
```

- **`websocket` 用 `test_instance`**（`:131`）——即本地的**测试适配器**（同 `run_test.py:6` 用的那个）。所以 `adapter='websocket'` 在生产环境里其实是个测试通道。
- **`kook` 传的是类本身 `KOOKBotInstance`，不是实例**（`:134`）——与其它分支都不一样。
- **三个 `if` 是独立的，不是 `elif`**（`:90`、`:97`、`:130`、`:133`）——但三个集合互不相交，所以不会重复赋值。
- **适配器标识写错时的行为**：`adapter` 值不在任何映射里时，`conf` 里**没有 `adapter` 键**，`AmiyaBot(**conf)` 会用默认适配器——这会导致账号静默地用错适配器。

## 5. `FunctionUsed`（`:139-142`）与 `DisabledFunction`（`:145-148`）

```python
@table
class FunctionUsed(BotBaseModel):
    function_id: str = CharField(primary_key=True)   # :141
    use_num: int = IntegerField(default=1)           # :142

@table
class DisabledFunction(BotBaseModel):
    function_id: str = CharField(null=True)     # :147
    channel_id: str = CharField(null=True)      # :148
```

- `FunctionUsed`：**`function_id` 直接作主键**；`use_num` 默认 `1`（`:142`）——**默认值是 1 而不是 0**，新建记录即代表「用过一次」。消费方 `core/server/dashboard.py:24-25`。
- `DisabledFunction`：**两个字段都可空**且**没有主键、没有唯一约束**——同一对 `(function_id, channel_id)` 可以重复插入，**去重责任在插件侧**。语义是「某频道禁用某功能」，`channel_id` 为 NULL 时表示全局禁用；**具体语义由使用方插件决定**（宿主只提供表）。

## 7. `Pool` — 卡池（`:168-240`）

**本仓库语义最复杂的一张表**，字段注释（`:173-214`）是理解抽卡逻辑的关键。

```python
pool_name        = CharField(unique=True)                # :170
pool_uuid        = CharField(null=True, default='')      # :172
pool_description = CharField(null=True, default='')      # :178
pool_image       = CharField(null=True, default='')      # :183
limit_pool       = IntegerField()                        # :188  必填
is_classicOnly   = BooleanField(default=False)           # :199
is_official      = BooleanField(default=True)            # :203
```

| 字段 | 行号 | 类型/默认 | 语义 |
| --- | --- | --- | --- |
| `pool_name` | `:170` | `unique=True` | **卡池名唯一** |
| `pool_uuid` | `:172` | `default=''` | **区分同名非官方卡池** |
| `pool_description` | `:178` | `default=''` | 卡池描述；**为空时自动生成** |
| `pool_image` | `:183` | `default=''` | 卡池题图 URL |
| `limit_pool` | `:188` | **必填** | **卡池类型枚举**（见下） |
| `is_classicOnly` | `:199` | `False` | 填充干员是否只含中坚干员 |
| `is_official` | `:203` | `True` | 是否官方卡池 |

**`pool_uuid` 的设计动机**（注释 `:173-176`）：*「用于区分同名非官方卡池，因为非官方卡池是可能会有同名的情况的，而数字Id不适用于远端数据库」*——`pool_name` 的 `unique=True` 只约束同一张表；非官方卡池在**不同用户的导入数据**里可能同名。用 uuid 做业务身份，避免依赖自增数字 id（跨库不可移植）。

### 7.1 `limit_pool` 枚举（注释 `:189-197`）

| 值 | 含义 |
| --- | --- |
| `0` | 常规寻访 |
| `1` | 限定寻访 |
| `2` | 联合寻访 |
| `3` | 前路回响 |
| `4` | 中坚寻访 |
| `5` | 其他寻访 |

**这个枚举在业务代码里被大量使用**：

- `pluginsDev/src/arknights/gacha/gachaBuilder.py:132-143` 按 `limit_pool` 给六星 up 概率兜底默认值：`0→0.5`、`1→0.7`、`2→1`、`3→1`、`4→1`、`5→1`。
- `:150-151` 五星：`limit_pool == 2` → `1`。
- `:177-178` `__is_classic_only`：`limit_pool == 4` → `True`。
- `pluginsDev/src/arknights/gacha/main.py:94` 显示名：`"【限定】" if item.limit_pool != 0 else ""`。

**合并语义与 `limit_pool=2` 的特殊性**（`gachaBuilder.py:122-124` 注释）：

```
# limit_pool = 2 联合行动 的五星六星都只会出up干员
# limit_pool = 3 前路回响 的六星都只会出up干员
```

即 `2` 与 `3` 的 up 概率是 100%。

### 7.2 pickup 字段组（`:208-238`）

注释 `:208-214` 是最重要的语义说明，原文：

```
# 卡池Up干员，和Up干员的加总概率，设置为100即为联合寻访（只有Up干员）
# 如果各个Up干员的rate不一样，可以在干员名后面用竖线分隔权重，权重可以为负数
# 例如：'干员1|1,干员2|5,干员3|5'
# 所有Up干员加权平分rate给出的概率。剩下的由常规干员填充
# 概率为小数，大于1的概率值会被转换为1
# 概率为None视为0
# pickup_s 为 五倍权重提升的任意干员，或者1倍权重但是会在本池抽出的限定干员，注意：其他fillin干员，权重为1
```

| 字段组 | 行号 | 说明 |
| --- | --- | --- |
| `pickup_6` / `pickup_6_rate` / `pickup_s` | `:216-218` | 六星 up 名单 / up 概率 / 特殊权重名单 |
| `pickup_5` / `pickup_5_rate` / `pickup_s_5` | `:220-222` | 五星 |
| `pickup_4` / `pickup_4_rate` / `pickup_s_4` | `:224-226` | 四星 |
| `pickup_3` / `pickup_3_rate` / `pickup_s_3` | `:228-230` | 三星 |
| `pickup_2` / `pickup_2_rate` / `pickup_s_2` | `:232-234` | 二星；**rate 默认 `0`** |
| `pickup_1` / `pickup_1_rate` / `pickup_s_1` | `:236-238` | 一星；**rate 默认 `0`** |
| `version` | `:240` | `default=''` |

**关键差异：`pickup_6_rate`/`5`/`4`/`3` 的默认是 `None`（`:217`、`:221`、`:225`、`:229`），而 `pickup_2_rate`/`1_rate` 的默认是 `0`**（`:233`、`:237`）。这个不对称是有意的：1/2 星不存在 up 概念，概率恒为 0；而 3-6 星的 `None` 表示「旧池子没填，需要按 `limit_pool` 推导默认值」（`gachaBuilder.py:126-148` 的 `__get_pickup_rate`）。

**pickup 名单的字符串格式**：

- 逗号分隔干员名：`'干员1,干员2'`
- 可用 `|` 追加权重：`'干员1|1,干员2|5'`
- **权重可以为负数**：作用是减少权重——某个池子可以抽出其它六星但不能抽出能天使时，在 `pick_up_s` 里标记 `能天使|-1`，与 fillin 里的 `能天使|1` 相加使其权重为 0（注释 `:209`，动机见 `gachaBuilder.py:205-208`）。
- 解析实现：`gachaBuilder.py:266-285` 的 `__get_weight`——按 `,` 切分（`:273`），有 `|` 时取权重（`:276-278`），**同名干员权重累加**（`:280-283`）。
- `pool_is_official` 的兜底：`gachaBuilder.py:130` `if pool.is_official is None or pool.is_official is True` —— **显式判了 `None`**，因为老数据可能为 NULL。
- **概率归一化实现**：`gachaBuilder.py:182-264` 的 `__get_gacha`，注释 `:202` 说明「把权重放大 10000 倍」是为了规避浮点精度问题。

**数据来源**：远端卡池接口返回的字段与 `Pool` 表一一对应（含 `pool_uuid`、`limit_pool`、`is_classicOnly`、`is_official`、`pickup_6/5/4/s` 等）。客户端侧的拉取与落库逻辑见 `pluginsDev/src/arknights/gacha/main.py:33-49` 的 `sync_pool`，以及宿主控制台侧 `core/server/gacha.py:62-71` 的 `sync_pool` 端点。
