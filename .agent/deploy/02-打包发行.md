## 2. 版本获取与「是否需要构建」判断

- `:93-98`：`cos_url = f'https://cos.amiyabot.com/package/release/latest-{platform}.txt'`，

清理与目录准备：`:85` `folder = 'package'`；`:110-117` 若 `package/dist` 或 `package/jieba` 存在则 `rmtree`，

## 6. `version_file` 模板与写入

`:28-59` 是 PyInstaller 的 **Windows 版本信息资源文件**（`VSVersionInfo`），含：

- `FixedFileInfo(filevers=({file_ver}, 0), mask=0x3f, OS=0x4, fileType=0x1, subtype=0x0, ...)`
- `StringFileInfo` → `CompanyName='AmiyaBot'`、`ProductName='《明日方舟》QQ机器人'`、
  `ProductVersion`/`FileVersion`（同一变量）、`FileDescription`（含官网地址）、
  `OriginalFilename='AmiyaBot.exe'`、`LegalCopyright`
- `VarFileInfo([VarStruct(u'Translation', [2052, 1200])])`（2052 = 简体中文，1200 = Unicode）

`:177-180` 写入 `package/version.txt`：

```python
version_file.format(
    file_ver=', '.join(re.findall(r'v(\d+).(\d+).(\d+)', version)[0]),
    file_version=version,
)
```

- `re.findall(r'v(\d+).(\d+).(\d+)', version)[0]` 从 `v6.6.1` 提取 `('6','6','1')` 拼成 `6, 6, 1` 喂给 `filevers`。
- **正则里的 `.` 未转义**，会匹配任意字符，属宽松匹配。
- **坑**：若 `version` 不含 `v\d+.\d+.\d+` 形状，`[0]` 抛 `IndexError`，构建直接崩（无友好提示）。

## 7. PyInstaller 命令拼接

先 `cd C:` 再 `cd C:/path`，Windows 下切换盘的经典写法。

参数片段（`:188-200`）：

| 变量 | 行号 | 内容 |
| --- | --- | --- |
| `data_files` | `:188` | `[(abspath(jieba_copy).replace(' ','\\ '), 'jieba')]` |
| `add_ico_cmd` | `:189` | ` -i {local}/amiya.ico` |
| `add_version_cmd` | `:190` | ` --version-file=version.txt` |
| `add_datas_cmd` | `:191` | ` --add-data={src};{dest}`（Windows 用 `;` 分隔） |
| `playwright_install` | `:192` | `['set PLAYWRIGHT_BROWSERS_PATH=0', '{abspath(scripts)}/playwright install chromium']` |
| linux 覆盖 | `:194-198` | `add_ico_cmd = ''`、`add_version_cmd = ''`（**Linux 无 exe 图标/版本资源**）；`add_datas_cmd` 改用 `:` 分隔；`playwright_install` 改成 `PLAYWRIGHT_BROWSERS_PATH=0 {abspath(scripts)}/playwright install chromium`（**shell 环境变量前缀语法**，非 `set`） |
| `add_hidden_imports_cmd` | `:200` | ` --hidden-import=amiyabot.util --hidden-import=amiyautils` |

### `PLAYWRIGHT_BROWSERS_PATH=0`（`:192,198`）

playwright 的**特殊约定值**：设为 `0` 表示把浏览器**装进包内相对目录**
（`playwright/driver/package/.local-browsers`）而不是用户主目录，
这样 PyInstaller 打出的单文件程序才能带上浏览器、在用户机器上离线运行。

这与 Dockerfile 路径不同（见 [01-入口与Docker.md](01-入口与Docker.md)）——Docker 用镜像默认路径即可。

### `--hidden-import=amiyabot.util --hidden-import=amiyautils`（`:200`）

PyInstaller 靠静态分析收集模块，**动态 import（字符串导入、插件按名加载）的模块会被漏掉**，必须显式声明。
`amiyabot.util` 与 `amiyautils` 都是运行时才 import 的。

这与 `core/frozen.py` 是同一原因的两个手段：`frozen.py` 是**显式 import 清单**，
`--hidden-import` 是**显式声明清单**，两者互补（`core/frozen.py:11` 的 `from core.lib import baiduCloud` 即一例）。

### 三条命令（`:202-206`）

1. `pyi-makespec -F -n {setup_name}{add_ico_cmd}{add_version_cmd} {local}/amiya.py {add_datas_cmd}{add_hidden_imports_cmd}`
   —— `-F` 即 `--onefile`（单文件）、`-n` 指定产物名，**只生成 `.spec` 不直接构建**。
2. `*playwright_install` —— 安装 chromium 到包内。
3. `{abspath(scripts)}/pyinstaller {setup_name}.spec` —— 用上一步的 spec 实际打包。

`:208-214` 先 `print('execute:', cm)` 回显，再
`subprocess.Popen('&&'.join(cmd), shell=True, stdout=subprocess.PIPE, stderr=subprocess.STDOUT)`
把三条命令用 `&&` 串成一条 shell 命令；逐行读 stdout 转发到构建日志。

## 9. `package.py` 的坑

- `:211` `shell=True` + 拼接用户可控的 `version`：版本号里若含 shell 元字符会被执行（CI 内运行，风险有限）。
- `:211-214` **`Popen` 未 `wait()`、未检查 `returncode`** —— 构建失败（如 `pyi-makespec` 报错）时，
  后续代码仍会尝试打包 zip，得到**不完整/空的产物**，而脚本不会以非零码退出（**CI 可能误判成功**）。
- `:184-186` 盘符处理只针对 `folder`，而 `local`/`venv` 的绝对路径同样可能含空格，仅 `add-data`（`:188`）做了转义。
- `:104` 的版本相等判断依赖 CDN 可读；CDN 不可达时 `latest = ''`，于是**每次都会重新构建并覆盖发布**
  （因为 `'' != version`），可能造成无谓的重复发布。

## 10. `build/uploadFile.py`

77 行，腾讯云 COS 上传/删除封装 `COSUploader`。基于 `qcloud_cos` 包
（`:5`：`CosConfig`、`CosS3Client`、`CosClientError`、`CosServiceError`）。

### 构造与 region/bucket 探测（`:9-22`）

```python
def __init__(self, secret_id, secret_key, region='ap-guangzhou', bucket=None, logger_level=logging.DEBUG):
    if logger_level:
        logging.basicConfig(level=logger_level, stream=sys.stdout)
    config = CosConfig(Region=region, SecretId=secret_id, SecretKey=secret_key)
    self.client = CosS3Client(config)
    self.bucket = bucket or self.get_bucket_by_index(0)
```

- `:13` 默认 `region='ap-guangzhou'`（广州）；`:14` `bucket` 默认 `None`。
- `:17-18` `logger_level` 非 falsy 时**全局配置** `logging.basicConfig(..., stream=sys.stdout)`。
  **这就是 `core/cosChainBuilder.py:23` 传 `logger_level=logging.NOTSET` 的原因**——`NOTSET` 为 0（falsy），
  跳过 `basicConfig`，避免运行时组件污染全局日志配置。
- `:19` `CosConfig(Region, SecretId, SecretKey)` —— **不支持临时密钥 Token**。
- `:22` **bucket 探测**：未显式传入时调 `get_bucket_by_index(0)`；
  `get_bucket_by_index`（`:24-25`）返回 `self.client.list_buckets()['Buckets']['Bucket'][index]['Name']`
  —— 即**列举该账号下的全部 bucket 并取第 0 个**。
  所以 `COSQQGroupChainBuilder` 没传 bucket，实际用的是账号里**排第一的 bucket**。

### `upload_file(file, target, resume_times=10)`（`:27-37`）

```python
for i in range(0, resume_times):
    try:
        self.client.upload_file(Bucket=self.bucket, LocalFilePath=file, Key=target)
        break
    except CosClientError or CosServiceError as e:
        print(e)
```

- **重试 10 次**（`:28`），成功即 `break`。
- **缺陷（`:36`）**：`except CosClientError or CosServiceError as e` 中 `or` 是**布尔或**，
  求值为 `CosClientError`（第一个真值类）——等价于 `except CosClientError`。
  **`CosServiceError` 永远不会被单独捕获**，会直接冒泡。这是把 `except (A, B)` 元组语法误写成 `or` 的经典 bug。
- **缺陷**：异常仅 `print(e)`，**不 sleep、不加退避**，10 次失败后**静默返回 `None`**
  ——调用方（如 `core/cosChainBuilder.py:59,72,85`）无法感知上传失败，
  而框架已拿到 `/cos/xxx.png` 形式的 URL，用户看到**图片裂图**却查不到错误日志。
- `resume_times=0` 时循环不执行，直接什么都不做。

### `delete_file(files)`（`:39-53`）

支持 `list` 或单个 `str`（非 list 时包装为单元素列表，`:40-41`）；把每个文件转成 `{'Key': file}`（`:44-45`）；
调 `self.client.delete_objects(Bucket=..., Delete={'Quiet': 'true', 'Object': delete_list})`（`:47-53`）
—— **批量删除**（COS 单次上限 1000 个 Key），`Quiet='true'` 表示只返回失败项。

### `delete_folder(folders, max_keys=100)`（`:55-77`）

按前缀**分页列举后批量删**：

- `:56-57` 同样兼容单值/list。
- `:61-74` 对每个 folder 循环：
  - `:65` `list_objects(Bucket=..., Prefix=folder, Marker=marker, MaxKeys=max_keys)` —— 用 `Prefix` 模拟「目录」。
  - `:67-68` 有 `'Contents'` 则把 `item['Key']` 全收进 `file_list`。
  - `:70-71` 有 `'NextMarker'` 则更新 `marker` 继续翻页。
  - `:73-74` `response['IsTruncated'] == 'false'` 时结束循环。
- `:76-77` 收齐后一次性 `self.delete_file(file_list)`。

### `uploadFile.py` 的坑

- `:73` 用**字符串**比较 `== 'false'` —— `qcloud_cos` 的 `IsTruncated` 返回字符串而非 bool，
  写法正确但脆弱（若 SDK 改为返回 bool，`True == 'false'` 恒假，循环永不结束）。
- `:70-71` 依赖 `NextMarker`；COS 在**未指定 `Delimiter`** 时可能**不返回 `NextMarker`**，
  此时 `marker` 保持上轮值，存在**死循环**风险（保险做法是用最后一个 Key 当 marker）。
- `delete_folder` 对**空目录/无匹配**不做处理（`file_list` 为空则跳过）；COS 是扁平存储，
  删除前缀下所有 Key 即等价删除目录。
- `delete_file` 未做单次 1000 Key 的分片；`delete_folder` 在**目录内对象超过若干页**时会把所有 Key
  攒进一个列表再一次性提交，大目录可能超出 COS 单请求限制（`max_keys=100` 只限制**列举**的分页大小，
  不限制最终删除批大小）。
