# 运行入口脚本

三个根目录脚本：`run_build.py`（构建分发）、`run_test.py`（插件源码调试）、`run_plugin_server.py`（插件商店后端）。

`run_test.py` 是**改插件后端到端验证的主路径**——直接装载源码目录的插件对象，绕过 zip 打包。

相关：[02-打包发行.md](02-打包发行.md)（`build` 函数）、[01-入口与Docker.md](01-入口与Docker.md)（`run_amiya`）。

---

## 1. `run_build.py`（30 行）

- `:6-17` **自己内联了一份 `argv`**（与 `core/util/common.py:34-45` 逻辑完全相同），
  而不是 `from core.util import argv` —— 因为构建脚本要在**依赖未装齐**的环境运行，
  不能 import `core`（会拉进 amiyabot 等一堆依赖）。
- `:20-21` 取 `--type`。
- `:23-26` `package` 分支：**延迟导入** `from build.package import build`，
  调 `build(argv('version'), argv('force'), argv('upload'))`
  —— 参数直接对应 `build/package.py:88` 的 `build(version, force=False, upload=False)`。
- `:27-30` `plugins` 分支：`from pluginsDev.buildPlugins import build`，
  调 `build(argv('folder') or 'plugins', argv('upload'))`（默认输出到 `plugins/`）。

用法：

```bash
python run_build.py --type package --upload      # 打包宿主并上传（CI 用）
python run_build.py --type package --version v6.6.2 --force
python run_build.py --type plugins               # 打包插件到 plugins/
```

| 参数 | 作用 |
| --- | --- |
| `--type package\|plugins` | 选择构建目标 |
| `--version vX.Y.Z` | 覆盖 `.github/publish.txt` 的版本号（见 [02-打包发行.md](02-打包发行.md)） |
| `--force` | 跳过「版本未变」检查（`build/package.py:104`） |
| `--upload` | 构建后上传 COS（读环境变量 `SECRETID`/`SECRETKEY`） |
| `--folder <dir>` | 仅 plugins 分支：输出目录（默认 `plugins`） |

## 2. `run_test.py`（26 行）

**源码调试法**：不开 QQ，用框架的 `test_instance` 起一个本地测试适配器。

```python
from amiyabot import AmiyaBot
from amiyabot.adapters.test import test_instance
from amiya import bot as main_bot, run_amiya

bot = AmiyaBot(appid='test', token='', adapter=test_instance('127.0.0.1', 32001))   # :6
bot.combine_factory(main_bot)                                                      # :7
```

- `:6` 测试适配器监听 `127.0.0.1:32001`（空 token）。
- **`:7` `bot.combine_factory(main_bot)`** —— 把主 bot 的工厂并入测试 bot，
  使**主程序的全局配置/事件与测试 bot 共享**，从而不必重复配置。

### 源码调试法（`:11-21`）

```python
if __name__ == '__main__':
    from pluginsDev.src.arknights.arknightsGameData import bot as resource      # :11
    from pluginsDev.src.replace import bot as replace                           # :12
    from pluginsDev.src.arknights.operatorArchives import bot as plugin         # :15

    async def install_plugin():
        bot.install_plugin(resource)          # :19
        bot.install_plugin(replace)           # :20
        bot.install_plugin(plugin)            # :21

    run_amiya(bot.start(launch_browser=True), install_plugin())                 # :26
```

- 插件是**直接 import 源码模块**（各自的 `bot` 对象），而不是从 `plugins/*.zip` 加载
  —— 改插件源码立即生效，无需打包。
- `:19-21` 三个 `install_plugin` 注册进测试 bot；典型组合是「gamedata（数据基础）+ replace（核心）+ 待测插件」。
- `:24` 注释提示另一种方式：`bot.install_plugin('plugins/amiyabot-arknights-gamedata-1.0.zip', extract_plugin=True)`
  —— 从 zip 安装，用于验证发布包。
- `:26` 复用 `amiya.py:11` 的 `run_amiya`，额外传入「安装插件」协程；
  `amiya.py:17` 会把 `install_plugin()` 协程 `create_task` 化，与 `bot.start` 并发。

### 已知问题

`:26` 的 `run_amiya(...)` 是**位置参数**，而 `amiya.py:11` 的签名是 `run_amiya(tasks: List[Coroutine] = [])`
—— 传入两个协程**不会被自动包成列表**，会触发 `TypeError`。
即该脚本按当前 `amiya.py` 签名**已不可直接运行**。

## 3. `run_plugin_server.py`（52 行）

启动**插件商店后端**的入口（`pluginsServer/` 是私有仓库，其实现不在本公开仓库中说明）。

- `:6` `from amiya import run_amiya` —— 复用启动器。
- `:7` `from amiyabot.util import argv` —— **用框架自带的 `argv`**，不是 `core.util` 的；
  这也是 `core/util/common.py:34` 保留一份重复实现的原因（两套环境各用各的）。
- `:8` `from pluginsServer.src import server, api` —— `api` 被导入以触发路由注册（side effect）。
- `:10-11` `AFDIAN_USER = argv('afdian-user')`、`AFDIAN_TOKEN = argv('afdian-token')`
  —— 爱发电（Afdian）赞助查询凭据，从命令行读。

### `/get_sponsors` 路由（`:14-48`）

```python
@server.server.app.get('/get_sponsors')          # :14-15
async def get_sponsors():
    if not AFDIAN_TOKEN or not AFDIAN_USER:
        return []                                # :16-17
```

- `:14-15` **注册新路由**，挂到后端服务的 `server.server.app`。
- `:16-17` 凭据缺失时直接 `return []`。
- `:19-46` 分页拉取爱发电赞助列表：
  - `:23` `while curr_page <= total_page` 翻页；`total_page` 初值 1（首次请求后由响应更新）。
  - `:24-33` 构造请求体：`ts = int(time.time())`，`params = json.dumps({'page': curr_page})`，
    `sign = md5(f'{AFDIAN_TOKEN}params{params}ts{sec}user_id{AFDIAN_USER}')`
    —— 爱发电开放平台的**签名规则**（token 与各字段按固定顺序拼接的 MD5），拼接串格式必须完全一致。
  - `:35` `url = 'https://afdian.com/api/open/query-sponsor'`。
  - `:37-44` `aiohttp.ClientSession().post(url, data=json.dumps(data), headers={'Content-Type':'application/json'})`；
    `res_content['ec'] == 200` 时累加 `data['list']` 并更新 `total_page`，否则 `break`。
  - `:46` `curr_page += 1`。
  - `:48` 返回 `json.dumps(sponsor_list, ensure_ascii=False)`（**返回字符串**而非对象）。
- `:51-52` 直接运行本文件时 `run_amiya(server.server.serve())` —— 只传一个协程。

### 坑

- `:22` `sponsor_list = []` 与 `:42` 的 `+=` 累加，若某页 `ec != 200` 则**静默 break 并返回已收集的部分数据**
  ——调用方无法区分「没有赞助者」与「中途请求失败」。
- `:37` **每页都新建一次 `ClientSession`**（在 while 内），反复建连开销大。
- `:30-32` 签名用 MD5 是爱发电平台规定，非本项目可自主选择。
- `:52` 的 `run_amiya(...)` 传参与 `amiya.py:11` 签名（`tasks: List[Coroutine] = []`）不匹配，
  与 `run_test.py:26` 是同一问题——**这两个脚本按当前代码均可能无法运行**。

## 4. 三个脚本与 `run_amiya` 签名的关系

`amiya.py:11` 定义 `run_amiya(tasks: List[Coroutine] = [])`，`amiya.py:17` 内部做 `[*init_task, *tasks]`。

| 脚本 | 调用写法 | 结果 |
| --- | --- | --- |
| `amiya.py:35` | `run_amiya([bot.start(...), app.serve()])` | 正确（列表） |
| `run_test.py:26` | `run_amiya(bot.start(...), install_plugin())` | **参数个数不匹配** |
| `run_plugin_server.py:52` | `run_amiya(server.server.serve())` | `tasks` 被赋为协程对象，`[*init_task, *tasks]` 展开不可迭代对象 |
