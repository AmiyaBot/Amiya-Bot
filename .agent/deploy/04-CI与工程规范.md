## 1. `.github/workflows/package.yaml`：三条 job

### 触发条件（`:3-8`）

```yaml
on:
    push:
        branches: [ V6-master ]
        paths: [ '.github/publish.txt' ]
    workflow_dispatch:
```

- `push` 到分支 **`V6-master`** 且**改动路径包含 `.github/publish.txt`**（`:5-6`）。
- `workflow_dispatch`（`:8`）允许手动触发。

### job 1：`publish-windows-package`（`:11-36`）

| 步骤 | 行号 | 内容 |
| --- | --- | --- |
| 环境 | `:12` | `runs-on: windows-latest` |
| checkout | `:14` | `actions/checkout@v5` |
| Python | `:16-20` | `actions/setup-python@v6`，`python-version: '3.12'`，`architecture: x64` |
| 装依赖 | `:22-28` | 升级 pip → `python -m venv venv` → 装 `pip wheel setuptools` → `pip install -r requirements.txt` → **`pip install pyinstaller`**（`:28`，不在 requirements.txt 里） |
| 构建发布 | `:30-36` | env 注入 `SECRETID`/`SECRETKEY`（`:32-33`，来自 GitHub secrets）；run `venv\Scripts\Activate.ps1` + `venv\Scripts\python run_build.py --type package --upload` |

这解释了 `build/package.py:63-64` 的 `venv`/`scripts` 默认值是 Windows 风格、
以及 `build/package.py:129` 用 `{scripts}\python.exe`。

### job 2：`publish-linux-package`（`:38-70`）

| 步骤 | 行号 | 内容 |
| --- | --- | --- |
| 环境 | `:39-40` | `runs-on: ubuntu-latest` + **`container: ubuntu:24.04`** —— 在 Ubuntu 24.04 容器内构建，保证 glibc/系统库与目标运行环境一致 |
| 系统依赖 | `:45-48` | `apt-get install -y build-essential wget curl unzip` |
| Python | `:50-53` | 3.12 |
| 装依赖 | `:55-61` | venv + `requirements.txt` + `pyinstaller` |
| 构建发布 | `:63-70` | env 除 secrets 外还有 **`PLATFORM: linux-x64`**（`:67`）；`python run_build.py --type package --upload` |

**注意** `:67` 的 `PLATFORM` 环境变量在 `build/package.py` 中**未被读取**
（`build/package.py:61` 用的是 `sys.platform`），所以它对产物命名不生效。

由于在 Linux 容器内构建，`build/package.py:194-198` 走 linux 分支；`:94` 读 `latest-linux.txt`。

### job 3：`publish-docker`（`:72-96`）

| 步骤 | 行号 | 内容 |
| --- | --- | --- |
| checkout | `:76` | `actions/checkout@v4`（前两个 job 用 v5，版本不统一） |
| QEMU | `:77-78` | `docker/setup-qemu-action@v3` —— 说明支持跨架构构建（如 arm64） |
| Buildx | `:79-80` | `docker/setup-buildx-action@v3` |
| 版本提取 | `:81-85` | `VERSION=$(cat .github/publish.txt \| sed 's/^v//')`，写入 `$GITHUB_ENV`；把 `v6.6.1` 变成 `6.6.1`（去掉 `v` 前缀） |
| 登录 | `:86-90` | `docker/login-action@v3`，secrets `DOCKERHUB_USERNAME`/`DOCKERHUB_TOKEN` |
| 构建推送 | `:91-96` | `docker/build-push-action@v6`：`context: .`、`push: true`、`tags: amiyabot/amiyabot:${{ env.VERSION }}, amiyabot/amiyabot:latest` |

- **双标签**（具体版本 + latest），正是 `dockersh/install.sh:157,164` 拉取的镜像名。
- 使用的 Dockerfile 就是根目录的 `Dockerfile`（见 [01-入口与Docker.md](01-入口与Docker.md)）。

### 三条 job 的关系

相互独立（无 `needs`），并行执行；都由 `publish.txt` 变更触发。
三条发布渠道**互不覆盖**：Windows 包更新 `latest-win32.txt`、Linux 包更新 `latest-linux.txt`
（`build/package.py:240`）、Docker 推 `amiyabot/amiyabot`。

## 2. `.github/publish.txt`：版本触发机制

文件内容为一行版本号，当前为 `v6.6.1`（`.github/publish.txt:1`）。

**触发链**：

```
改 publish.txt 并 push 到 V6-master
  → workflow "Publish packages" 启动（package.yaml:3-6）
  → run_build.py --type package --upload（:36,70）
  → package.py:100-102 读该文件得到 version
  → package.py:104 与 CDN 上的 latest-{platform}.txt 比较，相同则跳过
  → 构建成功后 upload_pack（package.py:228,240）把 publish.txt 内容上传为新的 latest-{platform}.txt
```

**`v` 前缀是硬约定**：

- `build/package.py:179` 的正则 `r'v(\d+).(\d+).(\d+)'` **要求版本号以 `v` 开头且形如 `vX.Y.Z`**。
- Docker job 又用 `sed 's/^v//'` 去掉它（`package.yaml:83`）。

**版本号必须写成 `vX.Y.Z`**，否则 Windows/Linux 打包会 `IndexError`（`build/package.py:179`）。

## 3. `black.sh`（1 行）

```bash
black amiya.py build core pluginsDev pluginsServer --skip-string-normalization --line-length 120
```

| 参数 | 含义 |
| --- | --- |
| 作用范围 | `amiya.py`、`build`、`core`、`pluginsDev`、`pluginsServer`（`run_*.py`、`entrypoint.py` **不在**范围内） |
| `--skip-string-normalization` | **保留单引号**，不强制转双引号——这是本项目代码普遍用单引号的原因 |
| `--line-length 120` | 行宽上限 120（black 默认 88），是本项目长行较多的原因 |

参数直接写在脚本里，仓库根没有 `pyproject.toml`。

用法：`bash black.sh`。

## 4. `.editorconfig`（9 行）

- `root = true`（`:1`）：到此文件为止，不再向上级目录查找 `.editorconfig`。
- `[*]`（`:3`）对**所有文件类型**生效：

| 行号 | 规则 |
| --- | --- |
| `:4` | `charset = utf-8` |
| `:5` | `indent_style = space` |
| `:6` | `indent_size = 4` |
| `:7` | `end_of_line = lf` |
| `:8` | `insert_final_newline = true` |
| `:9` | `trim_trailing_whitespace = true` |

**强制 LF 换行 + UTF-8 无 BOM + 4 空格缩进 + 文件末尾空行 + 去行尾空格**。
没有针对特定语言的覆盖段（如 `[*.py]`），全部走通用规则。

### 与配置模块的关系

`:15-17` 忽略的三个 yaml 由 `core/config/*.py` 的 `init_config_file` 在**首次启动时自动创建**
（见 [../tools/01-配置.md](../tools/01-配置.md)）。它们**不入库**，所以本地能看到但不受版本控制。

**对比**：`config/database.yaml`、`prefix.yaml`、`server.yaml` **未**被 ignore，属被追踪的默认配置，
由 `entrypoint.py` 在容器启动时改写（见 [01-入口与Docker.md](01-入口与Docker.md)）。

**注意** `*.zip`/`*.png`/`*.ttf` 是**全局通配**（不限目录），但仓库内 `plugins/` 与 `resource/` 下确实存在这些文件
——因为整个目录已被 ignore，本地文件仍在磁盘上（**不追踪 ≠ 不存在**）。

**与打包的交叉点**：`build/package.py:166` 会把 `config/` 当前磁盘内容整个 `copytree` 进发布包，
因此本地构建时**可能把含 COS 密钥的个人配置打进包**；CI 从干净 checkout 构建故无此问题
（详见 [02-打包发行.md](02-打包发行.md)）。

## 6. `requirements.txt`（16 行）

| 依赖 | 行号 | 用途 |
| --- | --- | --- |
| `amiyabot==2.1.1` | `:1` | **框架本体，精确固定版本**；`QQGroupChainBuilder`、`download_sync/async`、`argv` 都来自它 |
| `amiyautils~=0.0.5` | `:2` | **显式钉住的传递依赖**（`amiyabot` 亦声明 `~=0.0.5`）。2.1.1 的 `builtin/message/structure.py:8` 需要 `EventLoop`，该符号仅 0.0.5 提供；若为 0.0.4 则 `import amiyabot` 直接 `ImportError`。详见 `.agent/amiyabot/01-安装与导出.md` §1.3 |
| `jionlp~=1.5.23` | `:3` | `core/util/common.py:8` 的 `extract_time` + `build/package.py:171-175` 的词典打包 |
| `pypinyin~=0.54.0` | `:4` | `core/util/common.py:13` 的 `text_to_pinyin` |
| `attridict~=0.0.9` | `:5` | `core/util/yamlManager.py:3,24` 把 YAML 转点号可访问对象 |
| `cos-python-sdk-v5~=1.9.37` | `:6` | `build/uploadFile.py:5` 的 `qcloud_cos` |
| `gitpython~=3.1.44` | `:7` | `core/lib/gitAutomation.py:3` |
| `jsonschema~=4.24.0` | `:8` | 插件 `config_schema.json` 校验 |
| `srsly~=2.5.1` | `:9` | `core/frozen.py:3` 显式 import（打包收集用） |
| `requests-html~=0.10.0` | `:10` | `run_in_thread_pool(HTMLSession().get, url)` |
| `lxml_html_clean~=0.4.2` | `:11` | `requests-html` 的运行时依赖补丁件 |
| `baidu-aip~=4.16.13` | `:12` | `core/lib/baiduCloud.py:2` |
| `chardet~=5.2.0` | `:13` | 编码探测 |
| `jinja2~=3.1.6` | `:14` | 模板渲染（图片生成） |
| `opencv-python~=4.11.0.86` | `:15` | 图像处理（OCR 前处理等） |
| `tencentcloud-sdk-python~=3.0.1411` | `:16` | 腾讯云 SDK |

**要点**：

- `amiyabot` 用 `==` **精确锁定**（`:1`），其余用 `~=`（兼容性版本，允许补丁/次版本浮动）
  —— 框架 API 稳定性是硬约束（`core/` 大量继承其内部类，如 `QQGroupChainBuilder`）。
- **`amiyautils` 是唯一被显式钉住的传递依赖**（`:2`）：`amiyabot` 自身已声明 `amiyautils~=0.0.5`，此处显式重复是为防止「只升 `amiyabot` 而 `amiyautils` 停留 0.0.4」导致启动期 `ImportError`（`~=0.0.5` 语义为 `>=0.0.5, ==0.0.*`，排除 0.0.4）。
- ⚠️ **Docker 升级不会自动重装依赖**：`Dockerfile` 仅在**构建期** `RUN pip install -r requirements.txt`，而 `entrypoint.sh` 全程不跑 pip（`entrypoint.py:9` 只装 `pyyaml`）。升级镜像后 `/amiyabot` 数据卷里的旧 `amiyautils` 会被沿用，须重建镜像并清理环境，或在卷内手动 `pip install 'amiyautils~=0.0.5'`。
- **`pyinstaller` 不在其中**，由 CI 单独安装（`package.yaml:28,61`）。
- **`paddleocr`/`paddlepaddle` 不在其中**，但 `pluginsDev/src/arknights/recruit/main.py:263,279` 用了
  `paddle_ocr.ocr` / `pipe.read` —— 它是**插件级可选依赖**，运行时按需安装。
- **`playwright` 不在其中**，但 `Dockerfile:27` 与 `build/package.py:192,198` 都调用它
  —— 作为 `amiyabot` 的依赖被间接引入。

`Dockerfile:13,26` 与 CI（`package.yaml:27,60`）都 `pip install -r requirements.txt`。

## 7. `.gitmodules`（6 行）

声明两个 **git submodule**：

| 行号 | 名称 | 路径 | 上游 |
| --- | --- | --- | --- |
| `:1-3` | `pluginsServer` | `pluginsServer` | `https://github.com/AmiyaBot/Amiya-Bot-plugins-server.git` |
| `:4-6` | `pluginsDev` | `pluginsDev` | `https://github.com/AmiyaBot/Amiya-Bot-plugins.git` |

**重要含义**：这两个目录是**独立仓库**，主仓库只记录 commit 指针。
`pluginsServer` 是**私有仓库**，其实现与文档不在本公开仓库中说明。
所以文档中大量 `pluginsDev/src/...` 的行号证据**属于 submodule 的内容**，
主仓库更新 submodule 指针后需重新核对。

常用命令：

```bash
git submodule update --init --recursive   # 首次克隆后初始化
git submodule status                      # 查看指针
```

`run_build.py --type plugins`（`:27-28`）走 `pluginsDev.buildPlugins.build` 把插件源码打包到 `plugins/`。
