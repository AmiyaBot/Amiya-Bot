# 插件总览与通用机制

pluginsDev 子模块（Amiya-Bot-plugins）19 个插件的总表，以及所有插件共用的机制：实例类型、包结构、
装饰器语义、`event_bus` 事件契约、依赖拓扑与安装顺序、对 core 的依赖面。

**各插件的实现细节写在各插件自己的目录下**，见 `pluginsDev/src/<插件>/DEVELOP.md`。
插件目录中的 `README.md` / `README_USE.md` 是给**用户看的使用指引**（由插件实例的
`document=` / `instruction=` 参数加载，宿主 `功能/帮助` 指令会渲染它们），与 `DEVELOP.md` 分工不同。

## 二、插件实例类型

- 基础类 `PluginInstance` 由 amiyabot 框架提供，构造参数为 `name / version / plugin_id / plugin_type / description / document / priority`（参数形状见 `core/plugins/customPluginInstance/amiyaBotPluginInstance.py:41` 的 `super().__init__(...)`）。
- `core.AmiyaBotPluginInstance` 继承 `PluginInstance`（`core/plugins/customPluginInstance/amiyaBotPluginInstance.py:23`），额外提供：
  - `instruction` — 使用者说明文档路径（`amiyaBotPluginInstance.py:33,43`）
  - `requirements` — 插件间依赖声明（`amiyaBotPluginInstance.py:34,44`）
  - `channel_config_default` / `channel_config_schema` — 按频道配置（`amiyaBotPluginInstance.py:35-36,46,49`）
  - `global_config_default` / `global_config_schema` — 全局配置，二者均可传函数（`amiyaBotPluginInstance.py:37-38,47,50`）
  - `deprecated_config_delete_days` — 废弃配置清理（`amiyaBotPluginInstance.py:128` 起）
- `ai/blm` 进一步定义 `BLMLibraryPluginInstance(AmiyaBotPluginInstance, BLMAdapter)`（`ai/blm/src/common/blm_plugin_instance.py:27`）。
- `global_config_schema` 传函数的用例：`ai/blm` 运行时把可用模型名与 assistant 列表注入 schema 的 enum（`ai/blm/main.py:13-45,56`）。

## 三、插件包结构

- 每个插件目录含 `__init__.py`，内容统一为 `from .main import bot`（例：`admin/__init__.py`、`user/__init__.py`）。这是 `buildPlugins.py` 识别插件包的依据，也是框架加载入口。
- **zip 包内保留相对目录结构，并排除 `__pycache__`**（`pluginsDev/buildPlugins.py:82-85`）：
  - `plugins/amiyabot-admin-1.6.zip` → `__init__.py`、`README-public.md`、`README.md`、`logo.png`、`main.py`（5 个文件）。

## 四、装饰器清单与语义

| 装饰器 | 语义 | 用例 |
|--------|------|------|
| `@bot.on_message` | 消息处理器，支持 `keywords` / `verify` / `level` / `group_id` / `allow_direct` / `check_prefix` | 全项目 60+ 处 |
| `@bot.message_created` | 消息对象创建后、匹配前的钩子，可改写消息 | `admin/main.py:21`、`user/main.py:235`、`replace/main.py:89` |
| `@bot.message_before_handle` | 处理器执行前的总开关，返回 `False` 阻断本条消息 | `func/main.py:30`、`user/main.py:244`、`admin/main.py:27` |
| `@bot.message_after_handle` | 处理器执行后的统计钩子 | `func/main.py:76` |
| `@bot.message_after_send` | 消息发送后的钩子 | `user/main.py:259` |
| `@bot.on_event(name)` | 平台事件订阅 | `user/main.py:217`（`NudgeEvent`）、`user/main.py:226`（`notice.notify.poke`） |
| `@bot.timed_task` | 定时任务，支持 `each=N`（秒）与 `trigger='cron'` | 见下表 |

**`on_message` 参数取值分布**

- `level`（数值越小越先匹配）实际取值：`func` 用 5（`func/main.py:123,163`），`replace` 用 5（`replace/main.py:117`），`user` 昵称用 10（`user/main.py:43`），`ai/blm` 测试用 5（`ai/blm/main.py:60`）；arknights 侧 `operatorArchives` 基数为 `default_level = 8`（`arknights/operatorArchives/operatorCore.py:13`），`calculator` 用 99 与 3（`arknights/calculator/main.py:21,34`）。
- `allow_direct=True`：允许私聊触发，如 `func/main.py:83`、`talking/main.py:507`。
- `check_prefix=False`：不要求前缀（群内无需 @ 机器人），如 `talking/main.py:507`。
- `group_id`：互斥分组，同组内只执行一个。`user` 全量使用 `group_id='user'`（`user/main.py:43,90,100,...`），`weibo` 使用 `group_id='weibo'`（`weibo/main.py:428,457,470`），`arknights/operatorArchives` 用 `group_id='operator'`（`arknights/operatorArchives/main.py:20` 等），`arknights/gacha` 用 `group_id='gacha'`（`arknights/gacha/main.py:121` 等）。
- `verify`：自定义匹配函数，返回 `(bool, level, keypoint)` 或 `bool`。例：`talking/main.py:482-507` 的 `check_talk` 返回 `(True, 1, [reply, is_at])`；`user/mainBot.py:131-135` 的 `only_name` 返回 `(bool, 2)`。
- `keywords`：支持 `list[str]`、`str`、正则 `re.compile(...)`、`Equal('...')` 精确匹配。正则用例：`func/main.py:123` 的 `re.compile(r'开启(全部|所有)?功能')`；`Equal` 用例：`admin/main.py:81` 的 `Equal('频道信息')`。

**`timed_task` 全部用例**

| 位置 | 参数 | 用途 |
|------|------|------|
| `arknights/intellect/main.py:132` | `each=10` | 每 10 秒扫描理智已恢复满的用户并推送 |
| `arknights/material/main.py:277` | `each=3600` | 每小时刷新 yituliu 材料掉率数据 |
| `weibo/main.py:550` | `each=10` | 每 10 秒确保 WebSocket 连接（`skip=True` 非阻塞） |
| `weibo/main.py:555` | `trigger='cron', hour=0` | 每天 0 点清理过期图片缓存 |

## 五、`event_bus` 事件契约

| 事件 | 发布方 | 订阅方 |
|------|--------|--------|
| `gameDataFetched` | `arknights/arknightsGameData/builder/__init__.py:66`（`download_gamedata()` 内，GitAutomation 更新完成后） | `arknights/arknightsGameData/main.py:12` → `initialize_data()` |
| `gameDataInitialized` | `arknights/arknightsGameData/builder/__init__.py:56`（`initialize_data()` 内，解析完成后） | `arknights/recruit/main.py:168`、`arknights/material/main.py:227`、`arknights/stage/main.py:57`、`arknights/operatorArchives/operatorCore.py:26` |

**完整时序**

```
插件 install (priority=999, 最先)
  └─ autoUpdate 或 resource/gamedata 不存在 → download_gamedata()   arknightsGameData/builder/__init__.py:29-30
        └─ GitAutomation(...).update(['--depth 1'])                   builder/__init__.py:64
        └─ event_bus.publish('gameDataFetched')                       builder/__init__.py:66
              └─ @event_bus.subscribe('gameDataFetched') → initialize_data()   arknightsGameData/main.py:12-14
  └─ 否则直接 initialize_data()                                       builder/__init__.py:32
initialize_data()                                                      builder/__init__.py:52-56
  ├─ ArknightsConfig.initialize()
  ├─ ArknightsGameData.initialize()   → gamedata_initialize() 解析四类数据 + 写 OperatorIndex
  └─ event_bus.publish('gameDataInitialized')                          builder/__init__.py:56
        └─ 四个订阅者重建各自的索引
```

`gameDataFetched` 只有 1 个订阅者（gamedata 自己）；`gameDataInitialized` 有 4 个订阅者。

**四个订阅者的统一套路**

| 插件 | 订阅位置 | 反注册位置 | 回调动作 | 索引构建方式 |
|------|---------|-----------|---------|-------------|
| `operatorArchives` | `arknights/operatorArchives/operatorCore.py:26-33` | `operatorCore.py:22-23` | `bot.install()` | 整体重装：重跑三个 `init_*`（`operatorCore.py:17-20`） |
| `material` | `arknights/material/main.py:227-234` | `material/main.py:210-211` | `asyncio.create_task(MaterialData.init_materials())` | 只重建材料名列表 |
| `stage` | `arknights/stage/main.py:57-64` | `stage/main.py:42-43` | `bot.install()` | 整体重装：`create_dir` + `init_stages()`（`stage/main.py:38-40`） |
| `recruit` | `arknights/recruit/main.py:168-175` | `recruit/main.py:150-151` | `bot.install()` | 整体重装：`init_tags_list()`（`recruit/main.py:147-148`） |

四者回调结构一致，都带事件循环守卫：

```python
try:
    asyncio.get_running_loop()
except RuntimeError:
    pass
else:
    # 建索引 或 bot.install()
```

`asyncio.get_running_loop()` 是事件循环守卫：回调可能在没有运行中事件循环的线程中被触发，此时 `create_task` 会失败，索性什么都不做。代价是无事件循环时索引不会重建，插件将一直用空索引运行且没有日志。

**用 `bot.install()` 而非只建索引的原因**：这三个插件的索引构建依赖初始化顺序（`stage` 需先 `create_dir`、`recruit` 需先写完 tags.txt 再 `load_userdict`、`operatorArchives` 需三个 `init_*` 都跑完），复用 `install()` 最省事。副作用是 **`install()` 会被执行两次**（首次加载 + 事件触发）：`recruit/main.py:33-39` 的文件复制有 `os.path.exists` 守卫（幂等），而 `arknights/gacha/main.py:57-60` 的 `shutil.copyfile` 无守卫。

**反注册的必要性**：`event_bus` 订阅表是进程级全局的。若卸载/重载插件时不反注册，旧闭包仍持有已卸载插件的引用，下次事件发布会对失效对象调用 `install()`，造成重复初始化或异常。各订阅者均在 `uninstall()` 中解除（位置见上表）；`arknights/arknightsGameData/builder/__init__.py:34-36` 还额外从 `ArknightsGameData.initialize_methods` 移除 `gamedata_initialize`。

**不订阅 `gameDataInitialized` 的 arknights 插件**：`arknightsGameData`（发布者本身）、`enemy`、`gacha`、`calculator`、`intellect`。其中 `enemy` 和 `gacha` 确实消费 `ArknightsGameData` 却只在请求时按需读取。

### `priority` 与安装顺序

`arknightsGameData` 显式设置 `priority=999`（`arknights/arknightsGameData/builder/__init__.py:48`），其余插件默认 `priority=1`（`core/plugins/customPluginInstance/amiyaBotPluginInstance.py:32`）。安装顺序由 `core/plugins/__init__.py:46` 决定：

```python
for item in sorted(self.plugins.values(), key=lambda n: n.priority, reverse=True):
```

即**按 priority 降序安装**，999 让它第一个安装，从而在其它插件 `install()` 读取 `ArknightsGameData` 之前完成数据解析。全部安装完成后，再对所有 `AmiyaBotPluginInstance` 执行懒加载 `item.load()`（`core/plugins/__init__.py:57-59`）。

### 启动竞态

1. **`priority=999` 是唯一的顺序保证**。它只保证 `arknightsGameData` 最早 install，但其 `install()` 里 `download_gamedata()` / `initialize_data()` 都是同步阻塞调用（`builder/__init__.py:28-32,52-56`），其中 `GitAutomation(...).update()`（`builder/__init__.py:64`）是网络 + 磁盘操作。若框架逐插件顺序 install，解析会在下一个插件 install 前完成；若并发 install，后加载插件可能在数据就绪前被注册。
2. **`event_bus.publish` 是同步的、不重放**。`builder/__init__.py:56` 的发布发生在 `initialize_data()` 内，而该函数被 `install()` 直接调用（`builder/__init__.py:32`）。订阅者若在 gamedata 之后才 install，就永远错过这次 publish。这正是每个订阅者还要在 `install()` 里自建一次索引的原因——**事件的实际语义是「刷新」而非「首次初始化」**。
3. **`enemy` 与 `gacha` 的裸奔窗口**：
   - `enemy`：`ArknightsGameData.enemies` 为空时 `find_enemies` 返回空列表，用户看到「没有找到敌方单位的资料」（`arknights/enemy/main.py:189`），属功能降级。
   - `gacha`：`gachaBuilder.py:51` 调 `get_operators(...)`，`gachaBuilder.py:534-545` 才查 `game_data.operators`；`GachaBuilder.__init__` 的异常被 `arknights/gacha/main.py:123-127` 捕获并回「无法初始化卡池」。
4. **`gacha` 的 `sync_pool` 竞态**：`install()` 用 `asyncio.create_task(self.sync_pool())` 异步发起、不等待（`arknights/gacha/main.py:54`）。若用户在同步完成前抽卡，`Pool.get_or_none()` 可能为空、`get_official_pool` 取不到池子，`GachaBuilder.__init__` 抛异常。这是比 gamedata 竞态更常见的窗口，因为它是网络请求（`remote_config.remote.plugin + '/api/v1/gacha'`，`arknights/gacha/main.py:40`）。
5. **重复 install 的副作用**：`arknights/gacha/main.py:57-60` 的 demo 卡池 `shutil.copyfile` 无存在性守卫。
6. **`material` 的双重触发**：`install()` 起了 `create_task(save_yituliu_data())`（`arknights/material/main.py:207`），另有 `@bot.timed_task(each=3600)`（`arknights/material/main.py:277`）。两者都会做 `truncate_table()` + `batch_insert()`（`material/main.py:80-81`），若在启动时并发存在清表后写入竞态。
