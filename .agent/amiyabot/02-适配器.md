# 2. 适配器

本仓库 `BotAccounts.build_conf` 支持的适配器矩阵、各分支的构造参数，以及两种 QQ 群链构建器的差异。

相关：[安装与导出](01-安装与导出.md) · [消息构建](04-消息构建.md)

## 1. 权威来源

适配器的唯一权威来源是 `core/database/bot.py:70-136` 的 `BotAccounts.build_conf`。

基础 conf 构造（`core/database/bot.py:84-88`），实例化在 `:65`：

```python
conf = {
    'appid': item.appid,
    'token': item.token,

account.append(AmiyaBot(**conf))
```

即 `AmiyaBot(appid=..., token=..., private=bool, [adapter=...])`。

**私域模式**：`AmiyaBot(appid='...', token='...', private=True)` —— 私域机器人支持接收非 `@机器人` 的消息。见 [创建实例](https://www.amiyabot.com/develop/basic/index.html)。

### 3.2 `qq_group` / `qq_global` 分支

`core/database/bot.py:105-128`，默认端口回落 `8086`：

```python
port = item.http_port or 8086
opt = QQGroupChainBuilderOptions(item.host or '0.0.0.0', port, './resource/group_temp')

if cos_config.activate:
    conf['adapter'] = adapter(
        item.client_secret,
        default_chain_builder=COSQQGroupChainBuilder(opt),
        **shards,
    )
else:
    class PenetrationChainBuilder(QQGroupChainBuilder):
        @property
        def domain(self):
            return (
                penetration_config.ports[port] + '/resource'
                if port in penetration_config.ports
                else super().domain
            )

    cb = PenetrationChainBuilder(opt)
    conf['adapter'] = adapter(item.client_secret, default_chain_builder=cb, **shards)
```

**`QQGroupChainBuilderOptions` 构造签名**（`builder.py:75`，`@dataclass`）：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `host` | `str` | `'0.0.0.0'` | 本地临时文件 HTTP 服务地址 |
| `port` | `int` | `8086` | 本地临时文件 HTTP 服务端口（`PortSingleton` 的单例键） |
| `temp_path` | `str` | `'./resource'` | 临时文件目录，相对 CWD |
| `download_media` | `bool` | `False` | **2.1.5 新增**。`True` 时 http(s) 图片先由框架下载再上传（公网够不到内网图床时用） |
| `media_download_timeout` | `float` | `10.0` | 新增，框架侧下载超时（秒） |
| `media_max_bytes` | `int` | `20 * 1024 * 1024` | 新增，单文件上限，超过直接跳过 |
| `media_trust_env` | `bool` | `False` | 新增，下载时是否读 `HTTP_PROXY`/`NO_PROXY`（默认关，避免代理把内网请求劫持成 502） |

前三个字段仍是位置参数，`core/database/bot.py:107` 的 `QQGroupChainBuilderOptions(host, port, temp_path)` **无需改动**；新增字段全部有默认值，走原「平台侧下载」路径。

### 3.3 2.1.x 对 QQ 群 / 全域适配器的改动（宿主侧零改动）

| 变化 | 位置 | 影响 |
| --- | --- | --- |
| `ws_auth_token` 属性 | `qqGroup/__init__.py`、`qqGuild/__init__.py` | WebSocket 鉴权 token 由适配器自决：QQ 群用 `QQBot {AccessToken}`（旧的 `Bot appid.token` 会 4004），频道仍用 `Bot {appid}.{token}`。`core/` 不参与，无需改 |
| intents 增加 `INTERACTION` | `tencent/intents.py` | QQ 群订阅按钮回调 `INTERACTION_CREATE`，与全域一致 |
| `subscribe_group_member_event` | `QQGroupBotInstance.__init__` / `build_adapter` | 需要群成员进出事件时才置 `True`，默认关 |
| 工厂签名扩展 | `qqGroup/__init__.py`、`qqGlobal/__init__.py` | `qq_group` 仍是 `QQGroupBotInstance.build_adapter`，`qq_global` 在 2.1.x 也补了同形态的 `build_adapter`；两者新增 `subscribe_group_member_event=`、`default_chain_builder_options=`。调用姿势不变：`factory(client_secret, default_chain_builder=..., shard_index=, shards=)(appid, token)` |
| `upload_file` 支持 `file_data` | `qqGroup/api.py` | 富媒体上传三选一：`url`（平台侧下载）/ `file_data`（base64，≤5MB）/ `upload_id`（分片合并） |
| 全量群消息 `GROUP_MESSAGE_CREATE` | `qqGroup/package.py` | 见 [Message 对象](05-Message对象.md) §2.1：`is_at` 按 content 里的 `<@openid>` 标记推断，@ 标记从 `text` 剔除 |

## 5. `QQGroupChainBuilder` 与 `COSQQGroupChainBuilder`

`core/cosChainBuilder.py:12`：

```python
class COSQQGroupChainBuilder(QQGroupChainBuilder):
```

`COSQQGroupChainBuilder` **继承** `QQGroupChainBuilder`，是一个「把临时文件替换上传到腾讯 COS 后再发给 QQ 群」的替代实现。

覆写/新增的成员（`core/cosChainBuilder.py`）：

| 成员 | 行号 | 行为 |
| --- | --- | --- |
| `__init__` | `:13-24` | 调 `super().__init__(options)`；若 `cos_config.secret_id/secret_key` 均非空则创建 `COSUploader` |
| `domain`(property) | `:26-28` | 返回 `cos_config.domain + cos_config.folder`（父类返回本地穿透域名） |
| `start` | `:30-31` | 空实现 (`...`)，覆盖父类启动行为 |
| `temp_filename` | `:33-38` | 调 `super()` 得到 `(path, url)`，登记 `self.cos_caches[url] = f'{cos_config.folder}/{basename(path)}'` |
| `remove_file` | `:40-51` | 调 `super()` 后异步删除 COS 对象（`asyncio.create_task` + `run_in_thread_pool`） |
| `get_image` | `:53-64` | `http` 开头直接返回；否则 `super()` 后 `self.cos.upload_file(self.file_caches[url], self.cos_caches[url])` |
| `get_voice` | `:66-77` | 同上模式 |
| `get_video` | `:79-90` | 同上模式 |

`get_image`/`get_voice`/`get_video` 依赖两个字典：`self.file_caches`（由父类维护，`:60` 直接下标取值）与 `self.cos_caches`（由子类在 `:36` 维护）。

**选择逻辑**在 `core/database/bot.py:109-128`：`cos_config.activate` 为真用 `COSQQGroupChainBuilder`，否则用本地 `PenetrationChainBuilder`。开关见 `config/cos.yaml:1`（默认 `activate: false`）。

### 5.1 图片上送链路（2.1.5 后的两条路）

QQ 群的 `msg_type=7` 富媒体由 `PayloadBuilder.insert_media(url, file_type=1, download=None)` 组装（`builder.py:311`），它不是 `QQGroupChainBuilder` 的方法，子类**无法**通过覆写它改变行为：

| 路径 | 触发条件 | 谁去取图 |
| --- | --- | --- |
| 平台侧下载（默认） | `download`/`download_media` 为 `None`/`False` | 腾讯服务器拉 `url`，要求公网可达 |
| 框架侧下载 | `Chain(...).image(x, download=True)` 或 `options.download_media=True` | 框架下载 → ≤5MB 用 `file_data` 直传，更大走 `upload_prepare`/分片/合并（`qqGroup/media.py`） |

本仓库的 `COSQQGroupChainBuilder` 只覆写 `get_image`（本地图 → 上传 COS → 返回公网 URL），恰好落在「平台侧下载」路径上，因此 `cos.yaml` 开启时**不需要** `download_media`；只有把内网图床地址直接丢给 QQ 群时才需要打开它。

> 另一条备用路：`cos.yaml` 关闭且未配穿透时，本地图 URL 用的是内网 IP（`domain` = `{http}://{ip}:{port}/resource`），腾讯侧拉不到。此时把 `download_media=True` 传给 `QQGroupChainBuilderOptions`，框架就会自己从同一台机器的 `<内网IP>:<port>/resource/...` 取图再直传，可省掉 COS 与穿透。
