# 游戏数据契约

`core/resource/arknightsGameData.py` 是**纯契约/抽象定义，零业务实现**——只声明数据结构长什么样、谁负责填充。
具体数据（游戏 JSON、Wiki 抓取）的解析逻辑全在 gamedata 插件里。

相关：[03-外部服务.md](03-外部服务.md) 的 `GitAutomation`（插件用它拉数据仓库）；
插件内部实现见 [../plugins/](../plugins/) 系列文档。

### `initialize_methods` 机制

```python
@classmethod
def initialize(cls):              # :26-29
    for method in cls.initialize_methods:
        method(cls)
```

遍历调用每个注册的方法并传入 `cls`。**这是插件向核心注册数据填充逻辑的插槽。**

`get_real_name(operator: str = None)`（`:31-33`）只有 `...`（Ellipsis），是待实现桩。

`ArknightsGameDataResource`（`:36-47`）：三个 `@staticmethod` 桩

`get_voice_file(operator, voice_key, voice_type='')`（`:42`）、
`parse_template(blackboard, description)`（`:46`），全部只有 `...`。

## 7. 契约层的意义与坑

**意义**：`core` 只声明「数据结构长什么样 + 谁负责填」，数据来源与解析逻辑全在插件里，
因此**核心可以脱离数据独立打包发布**，玩家按需安装 gamedata 插件。

**坑**：

- **插件缺失时不报错**：没有 gamedata 插件时，访问 `ArknightsGameData.operators` 拿到的是空 dict
  （`:16` 的类属性默认值）而非异常——这是「插件缺失」类问题难以定位的原因。
- **可变默认值**（`:12-22,51-57`）：若不显式重置，多次 `initialize()` 会**累积**旧数据，
  热重载后可能出现「删掉的干员仍在 `operators` 里」。
- **`initialize_methods = [...]` 是赋值覆盖**（`builder/__init__.py:395`、`common.py:113`）：
  若将来有第二个插件也想注册，会把前一个插件的方法**整个冲掉**。当前是单插件独占，尚无冲突。
