# 配置模块

`core/config/` 下三类配置（COS / 远程 / 穿透）+ 配置文件的加载与默认值回写机制 `init_config_file`。
新增配置字段会自动补写进用户 yaml；`config/remote.yaml` 的修改会被启动流程覆盖，改它无效。

相关：[02-工具函数.md](02-工具函数.md) 的 `merge_dict`、[05-COS图床.md](05-COS图床.md) 的 `cos_config` 消费方。

## 1. 模块结构与导出

`core/config/__init__.py:1-3` 只有三行，把三个模块级单例再导出：

```python
from .cos import cos_config
from .remote import remote_config
from .penetration import penetration_config
```

**注意**：`import core.config` 会立刻触发三个 YAML 的加载与回写，以及 `remote_config` 构造时的一次 HTTP 请求。
任何 `from core.config import ...` 都带这两个副作用。

消费方一览：

| 消费点 | 用途 |
| --- | --- |
| `core/database/bot.py:3,109,121-122` | `cos_config.activate` 决定是否启用 COS；`penetration_config.ports[port] + '/resource'` 拼穿透地址 |

## 2. `cos.py` / `penetration.py`

`core/config/cos.py:5-11`：

```python
@dataclass
class CosConfig:
    activate: bool = False
    secret_id: str = ''
    secret_key: str = ''
    domain: str = ''
    folder: str = ''
```

- `core/config/cos.py:14-15`：`init(file)` 是 `init_config_file(file, CosConfig)` 的薄封装（`refresh=False`，走合并分支）。
- `core/config/cos.py:18`：模块级单例 `cos_config = init('config/cos.yaml')`，相对**进程 CWD** 解析路径，必须在仓库根启动。

`core/config/penetration.py:5-7`：

```python
@dataclass
class Penetration:
    ports: dict = field(default_factory=dict)
```

- `core/config/penetration.py:10-11`：`init(file)` → `init_config_file(file, Penetration)`。
- `core/config/penetration.py:14`：`penetration_config = init('config/penetration.yaml')`。

**默认值回写机制**：两个模块都走 `refresh=False` 分支，即「读旧文件 → 与 dataclass 默认值 merge → 整体 overwrite 写回」。
用户启动一次后，`config/cos.yaml`、`config/penetration.yaml` 即被补全成完整字段集。

磁盘现状：`config/cos.yaml` 为 5 个键（`activate: false` / `domain: ''` / `folder: ''` / `secret_id: ''` / `secret_key: ''`），
与 dataclass 字段一一对应；`config/penetration.yaml` 为 `ports: {}`。

## 3. `remote.py`：默认地址与远程覆盖

`core/config/remote.py:6-10` 的三个默认地址：

```python
cos     = 'https://cos.amiyabot.com'
plugin  = 'https://cdn.amiyabot.com'
console = 'http://106.52.139.57:8000'
```

`Remote.__init__`（`core/config/remote.py:12-23`）在对象构造时即发起一次网络请求：

1. `:14`：`requests.get(f'{self.plugin}/api/v1/remote')` —— 用**默认** plugin 地址，不是用户配置里的值。
2. `:16-17`：状态码非 200 或返回体没有 `code` 键则 `return`，保留默认值。
3. `:18-21`：`code == 200` 时用 `data['data']['cos'|'plugin'|'console']` **逐个覆盖**三个属性。
4. `:22-23`：裸 `except: pass`，静默吞掉所有异常（DNS 失败、超时、JSON 解析失败、KeyError 等）。

`RemoteConfig`（`:26-28`）是 `remote: Remote = field(default_factory=Remote)` 的包装；
`init` 在 `:31-32` 以 `init_config_file(file, RemoteConfig, True)` 调用，`refresh=True` 意味着
**每次都重新构造 `Remote` 并发起请求**（`core/util/yamlManager.py:52-55` 的 refresh 分支直接 `asdict(build_cls())` 覆盖写文件）。

**排查影响**：

- 用户改 `config/remote.yaml` 里的 `plugin` 地址**无效**：`RemoteConfig` 用 refresh=True，每次启动用默认值重建并覆盖写回，用户的修改被抹掉。
  `remote.yaml` 只是默认值的落盘快照。
- 真实生效的地址来自 `https://cdn.amiyabot.com/api/v1/remote` 的返回值。排查「插件下载 404 / 心跳打不通」时先怀疑这个接口返回了什么。
- `:22-23` 的裸 `except: pass` 使网络不通时**无任何日志**，表现为静默回落到默认地址——「内网/无外网」与「配置文件写错」两种故障表现相同，定位时需手动复现该请求。
- 若该接口被劫持或返回异常值，资源与插件市场流量会被导向第三方地址。

## 4. `init_config_file`：加载与默认值回写

`core/util/yamlManager.py:47-56`：

```python
def init_config_file(file: str, build_cls, refresh=False):
    config = {}
    if os.path.exists(file):
        config = YamlManager.read_yaml(file, _dict=True, _refresh=refresh)

    if not refresh:
        YamlManager.create_yaml(file, merge_dict(config, asdict(build_cls())), True)
    else:
        YamlManager.create_yaml(file, asdict(build_cls()), True)
    return YamlManager.read_yaml(file)
```

| 分支 | 行号 | 行为 |
| --- | --- | --- |
| 文件存在 | `:48-50` | 读为 dict（`_dict=True`）；不存在则 `config = {}` |
| `refresh=False`（默认） | `:52-53` | `merge_dict(用户配置, asdict(build_cls()))` → **用户已有键优先**、缺失键用 dataclass 默认值补上 → `overwrite=True` 整文件覆写 |
| `refresh=True` | `:54-55` | **丢弃用户配置**，直接写 dataclass 默认值（目前只有 `remote.py:32` 用它） |
| 返回 | `:56` | 再 `read_yaml(file)`（`_refresh` 取默认 `True`），以 `attridict` 返回，故可 `cos_config.secret_id` 点号访问 |

配套的 `YamlManager`（`core/util/yamlManager.py:11-44`）：

- `read_yaml`（`:15-28`）：带 `yaml_cache` 两级缓存（`_dict` / `attr`），`_refresh=True` 时绕过缓存。`:23-24` 非 `_dict` 时包装成 `attridict`。
- `create_yaml`（`:31-44`）：`:32-35` `SafeDumper.add_representer(None → '')` 让 `None` 序列化为空串而非 `null`；
  `:36` `create_dir(path, is_file=True)` 保证父目录存在；`:38-39` `overwrite=False` 且文件已存在时直接 `return False`。

### 新增配置字段的自动化与风险

**自动化**：在 dataclass 上加一个带默认值的字段，所有老用户的配置文件在下次启动时**自动补上该键**，无需写迁移代码。

**风险**：

1. 整文件 `overwrite` 重写会**丢失注释、键顺序、自定义格式**——用户手工加的注释会被无声抹掉。
2. 写回是「每次启动都执行」而非「仅在缺键时执行」，运行期故障（磁盘只读、权限不足）会**直接导致启动失败**，而非退化成「用默认值跑」。
3. `merge_dict` 对「类型不一致」是**静默覆盖用户值**：用户把 `ports: {}` 写成 `ports: []` 会被无声改回（见 [02-工具函数.md](02-工具函数.md)）。
4. `refresh=True` 的模块（`remote.py`）用户改了也没用，容易造成「配置不生效」的困惑。

### 哪些 yaml 入不入库

`.gitignore:15-17` 忽略 `config/cos.yaml`、`config/remote.yaml`、`config/penetration.yaml`
——它们含密钥（`secret_id`/`secret_key`）与机器相关地址，首次启动时由 `init_config_file` 自动创建。

对比：`config/database.yaml`、`prefix.yaml`、`server.yaml` **未**被 ignore，属被追踪的默认配置，
由 `entrypoint.py` 在容器启动时改写（见 [../deploy/01-入口与Docker.md](../deploy/01-入口与Docker.md)）。
